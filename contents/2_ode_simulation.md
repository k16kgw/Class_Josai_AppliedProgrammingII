### なぜ数値的に解く必要があるのか

- **解析解**：解析的な計算によって得られる解
  - 例：$x'=rx$，$x(0)=x_0$ に対する $x(t)=x_0e^{rt}$．
  - 解析的に求める際の制約：仮定を追加した複雑なモデルでは，解を明示的な数式で表すことが難しくなる場合が多い．

| 仮定 | 微分方程式 | 解析的な計算の方法と制約（初期時刻は0） |
| --- | --- | --- |
| 変化率が現在量に比例する | $x' = rx$ | $x_0 e^{rt}$ |
| 一人あたりの増加率が人口に対して線形に減少する | $x' = rx(1 - x/K)$ | 変数分離により解析解を求められる |
| 流入量と放流量を観測データで与える | $V' = Q_{\mathrm{in}}(t) - Q_{\mathrm{out}}(t)$ | 入力を補間し，その時間積分を計算する |
| 捕食によって2つの個体群が相互作用する | $x' = ax - bxy$<br>$y' = -cy + dxy$ | 一般の初期条件に対して，時間の関数としての解を初等関数で表すことは困難である |

- **数値解**：離散的な時刻における解の近似値．これを計算して状態変数の時間変化を調べる．
  - 数値解法の適用対象：観測データを入力とするモデルや，複数の状態変数をもつ連立微分方程式も扱える．

## 初期値問題

- **初期値問題**：微分方程式と初期条件をともに満たす関数 $x(t)$ を求める問題．

$$
\left\{
\begin{aligned}
    & \frac{dx}{dt} = f(t, x) \\
    & x(t_0) = x_0
\end{aligned}
\right.
$$

- 微分方程式 $x'=f(t,x)$：各時刻・状態における変化率を規定する．
- 右辺の関数 $f(t,x)$：時刻 $t$ に状態が $x$ であるときの変化率．現象に対する仮定を関数形で表す．
- 初期条件 $x(t_0)=x_0$：初期時刻 $t_0$ の状態を指定する．
- 初期値 $x_0$：初期時刻における状態変数の値．

- 解の存在と一意性（cf. 補遺1）：
  - 微分方程式 $x'=rx$ だけでは，初期値ごとに異なる解が存在する．
  - ここに初期条件を与えると解が一意に定まる．
  - 数理モデルを作成した場合には，解の存在と一意性は成り立っているものとして議論が進められることが多い．

### 例：指数的な増加と減衰

- この節の扱い：解法を学ぶための数学的な例として，$t$ と $x$ に物理的な単位を設定しない．
- 方程式：$x'=rx$．
- 初期条件：$x(t_0)=x_0$．
- 解析解：

$$
x(t) = x_0\,e^{r(t - t_0)}
$$

この解析解はpythonでは次のような関数として実装できる．

```python
def exponential_solution(t, x0, r, t0=0.0):
    """dx/dt = r x, x(t0) = x0 の解析解 x0 * exp(r (t - t0)) を返す．"""
    return x0 * np.exp(r * (t - t0))
```

```{dropdown} コードの補足

- [`np.exp(z)`](https://numpy.org/doc/stable/reference/generated/numpy.exp.html)：指数関数 $e^z$ を計算する．`z`がNumPy配列なら，各要素について計算する．
- `def`と`return`：`def`で関数を定義し，`return`で計算結果を呼び出し元へ返す．
- `t0=0.0`：引数`t0`を省略したときに使う値を指定する．
```

````{dropdown} 補足：解析解が初期値問題を満たすことの確認
$$
\frac{dx}{dt} = x_0\,r\,e^{r(t - t_0)} = r\,x(t)
$$

- 初期条件の確認：$t=t_0$ を代入すると $x(t_0)=x_0e^0=x_0$．
````

## Euler法：解の一次近似による時間発展の計算

### 導出

刻み幅 $h$ を十分小さいものとして，微分係数は差分商によって近似できる．

$$
x'(t) \approx \frac{x(t + h) - x(t)}{h}
$$

これを用いて微分方程式を置き換えれば

$$
\frac{x(t + h) - x(t)}{h} \approx f(t,x(t)).
$$

ここで次の時刻の値（$x(t+h)$）について整理すると

$$
x(t + h) \approx x(t) + h\,f(t, x(t)),
$$

となる．

次の命名規則（notation）に従い記号を定義する．

- 時刻の記号：$t_k=t_0+kh$．
- 近似値の記号：$x_k\approx x(t_k)$．

すると微分方程式は次の漸化式とみなすことができる．

$$
x_{k+1} = x_k + h\,f(t_k, x_k),
\qquad k = 0, 1, 2, \ldots.
$$

初期値 $x_0$ から更新式を繰り返し適用することで，任意の時刻までの $x$ の値を数値的に求めることができる．

```{tip} 注意：近似の正当性
微分方程式に対して $\approx$ で議論したことからも分かる通り，あくまで近似値を計算しているに過ぎない．
この手続きに従って得られる数値解が元の微分方程式の解の近似として妥当かどうかは，

- Euler法の収束定理・誤差評価（適切な条件のもとで，刻み幅 $h$ を0に近づけると数値解が厳密解に近づく）
- 解の存在と一意性

を確認する必要がある．
```

## Pythonによる実装

### Euler法の関数

- 入力：右辺の関数 $f$，計算区間，初期値，刻み幅，パラメタ．
- 処理：手計算と同じ更新式を繰り返す．
- 出力：時刻の配列と近似解の配列．

```python
def euler(rhs, t_span, x0, h, args=()):
    """前進Euler法で初期値問題 x' = rhs(t, x, *args), x(t0) = x0 を解く．

    rhs: 右辺の関数．rhs(t, x, *args) の形で呼び出す．
    t_span: (t0, t_end) 計算区間．
    x0: 初期値（実数のスカラー）．
    h: 正の刻み幅．最後のステップだけ必要に応じて短くする．
    args: rhs に渡すパラメタのタプル．
    戻り値: 時刻の配列 t と近似解の配列 x．
    """
    t0, t_end = t_span
    if h <= 0 or t_end <= t0:
        raise ValueError("h > 0，t_end > t0 を指定してください．")

    # 時間ステップを用意
    n_steps = int(np.ceil((t_end - t0) / h))
    t = t0 + h * np.arange(n_steps + 1)
    t = np.append(t[t < t_end], t_end)
    n_steps = len(t) - 1

    # 解の変数を用意
    x = np.zeros(n_steps + 1)
    x[0] = x0

    # 更新式の計算
    for k in range(n_steps):
        dt = t[k + 1] - t[k]
        x[k + 1] = x[k] + dt * rhs(t[k], x[k], *args)
    return t, x
```

```{dropdown} コードの補足

- `int(np.ceil(...))`：小数部分を切り上げ，整数型に変換する．例：`int(np.ceil(2.3))`は`3`．
- [`np.arange(n_steps + 1)`](https://numpy.org/doc/stable/reference/generated/numpy.arange.html)：0から`n_steps`までの整数を並べた配列．終了値`n_steps + 1`は含まない．
- `t[t < t_end]`：配列`t`から，`t_end`より小さい要素だけを取り出す．`np.append(..., t_end)`で末尾に終了時刻を加える．
- `np.zeros(n_steps + 1)`：全要素が0の配列を用意する．`x[0]`は先頭要素で，添字は0から数える．
- `range(n_steps)`：0から`n_steps - 1`までの整数を順に使い，`for`で更新を繰り返す．
- `args=()`と`*args`：追加パラメタをタプル（値をまとめたもの）で受け取り，`*args`で展開して右辺の関数へ渡す．`args=(r,)`なら`rhs(t[k], x[k], r)`という呼び出しになる．

- 対応する問題：実数の状態変数が1つで，$t_{\mathrm{end}}>t_0$ の初期値問題．
- 終了時刻の処理：区間を $h$ で割り切れない場合は，最後のステップを短くする．

  - 例：区間0〜10，$h=1.2$ では，$t=9.6$ まで1.2刻み，最後は0.4刻み．

- 右辺の関数：`rhs(t, x, パラメタ...)`の形式．`solve_ivp`と共通にする．
- 今回のパラメタ：増加率 $r$．
```

右辺の関数を準備する．

```python

    """dx/dt = r x の右辺．"""

```

```python
x0 = 100.0       # 初期値

```

```{dropdown} コードの補足

- `t, x = euler(...)`：関数が返した2つの配列を，それぞれ`t`と`x`で受け取る．

- `(r,)`：要素が1つのタプル．末尾のカンマが必要で，`(r)`だけではタプルにならない．
- `f"{error:10.2f}"`：変数の値を文字列に埋め込む書き方．ここでは表示幅10文字，小数点以下2桁で表示する．
```

## `solve_ivp`による数値シミュレーション

### 使い方

- Euler法の制約：高い精度を得るには，小さい刻み幅と多くのステップが必要．
- 実用的な解法：`scipy.integrate.solve_ivp`を使う．
- 既定の方法：Runge–Kutta法の一種であるRK45．導出は本講義の範囲外．
- 刻み幅の調整：各ステップの局所誤差の推定値に基づいて自動調整する．
- 許容誤差：局所誤差の制御に用いる値．計算区間全体の誤差の上限ではない．
- `t_eval`：出力時刻の指定．内部の刻み幅を直接指定するものではない．

```python
# 数値解を出力したい時刻
t_eval = np.linspace(t_span[0], t_span[1], 101)

sol = solve_ivp(exponential_rhs, t_span, [x0], t_eval=t_eval, args=(r,))

print("成功したか:", sol.success)
print("時刻の配列の形:", sol.t.shape)
print("解の配列の形:", sol.y.shape)
print("右辺を評価した回数:", sol.nfev)
```

- `exponential_rhs`：ここでは括弧を付けず，関数そのものを渡す．`solve_ivp`が計算中にこの関数を呼び出す．
- `.shape`：配列の各次元の大きさ．`(1, 101)`は，行が1つ，列が101個あることを表す．

引数と戻り値の対応を整理する．

| 引数・属性 | 意味 | 今回の値 |
| --- | --- | --- |
| 第1引数 | 右辺の関数 `rhs(t, x, *args)` | `exponential_rhs` |
| 第2引数 `t_span` | 計算区間 $(t_0, t_{\mathrm{end}})$ | `(0.0, 10.0)` |
| 第3引数 | 初期値．状態変数が1つでもリストで渡す | `[x0]` |
| `t_eval` | 解を出力する時刻の配列 | `np.linspace(0, 10, 101)` |
| `args` | 右辺に渡すパラメタのタプル | `(r,)` |
| `sol.t` | 出力時刻の配列 | 長さ101 |
| `sol.y` | 解の配列．行が状態変数，列が時刻 | 形は (1, 101) |
| `sol.y[0]` | 1つ目の状態変数の時系列 | $x(t)$ |

- 配列の次元：状態変数が1つでも，`sol.y`は2次元配列．
- 状態変数が1つの場合：`sol.y[0]`で $x(t)$ の近似値を取り出す．
- 状態変数が2つの場合：`sol.y[0]`と`sol.y[1]`を使う（第10回など）．

### Euler法および解析解との比較

```python
x_ivp = sol.y[0]
x_exact_eval = exponential_solution(sol.t, x0, r)

print(f"solve_ivp の x(10) = {x_ivp[-1]:.4f}")
print(f"解析解の x(10)     = {x_exact_eval[-1]:.4f}")
print(f"誤差               = {x_ivp[-1] - x_exact_eval[-1]:.4f}")
print(f"最大絶対誤差（出力時刻上） = {np.max(np.abs(x_ivp - x_exact_eval)):.4f}")

t_euler, x_euler = euler(exponential_rhs, t_span, x0, 0.01, args=(r,))
print(f"Euler法 h=0.01 の x(10) = {x_euler[-1]:.4f}，ステップ数 = {len(t_euler) - 1}")
```

- `x_ivp - x_exact_eval`：同じ形のNumPy配列どうしでは，対応する要素ごとに引き算する．
- `np.abs(...)`と`np.max(...)`：各要素の絶対値を求め，その最大値を取り出す．ここでは出力時刻上の最大絶対誤差になる．

- 今回の結果：`solve_ivp`は右辺の評価が数十回で，Euler法1000ステップより小さい誤差．
- 比較の範囲：今回の方程式・計算条件での結果．一般の問題で同じ効率を保証するものではない．
- 今後の使い分け：実際の計算には原則`solve_ivp`，原理の理解にはEuler法を用いる．
- 注意が必要な例：観測データの補間など，右辺が滑らかでない場合（第6回）．

```{tip} 許容誤差の指定

- 相対許容誤差：`rtol`．既定値は`1e-3`．
- 絶対許容誤差：`atol`．既定値は`1e-6`．
- 判定基準：状態変数が1つなら，局所誤差の推定値を`atol + rtol * abs(x)`と比較する．
- 指定例：`solve_ivp(..., rtol=1e-8, atol=1e-10)`．許容誤差を小さくすると，一般に評価回数が増える．
- 精度の確認：解析解との比較，または許容誤差を小さくした再計算．
- 参照先：[SciPy公式ドキュメント](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html)．
```

````{dropdown} 演習3の確認：コード例
```python

    """dx/dt = -k x の右辺．"""
    return -k * x


k = 0.3                      # 減衰率 [1/時間]

sol_decay = solve_ivp(decay_rhs, t_span_decay, [x0_decay], t_eval=t_eval_decay, args=(k,))

x_decay_exact = x0_decay * np.exp(-k * sol_decay.t)

if half_indices.size > 0:

else:
    print("計算区間内では初期値の半分以下になっていません．")
print(f"解析解の半減期 ln2/k:  {np.log(2) / k:.2f} 時間")

fig, ax = plt.subplots(figsize=(7, 4))
````

## 誤差の分類

- 分類の目的：数値解と観測値の差の原因を整理し，改善する対象を選ぶ．
- 比較の条件：モデルの形・パラメタ・初期値を固定し，数値計算の設定だけを変える．
- 分類の限界：各要因は相互に影響するため，残差だけから個別に分離できるとは限らない．

| 種類 | 何に由来するか | 刻み幅・許容誤差を変えると減るか | 今回の例 | 詳しく扱う回 |
| --- | --- | --- | --- | --- |
| 数値解法の誤差 | 離散化による近似や有限精度の演算 | 適切な条件では打ち切り誤差を減らせるが，丸め誤差には限界がある | Euler法 $h = 1$ での $x(10) = 619.2$（解析解 $738.9$，符号付き誤差 $-119.7$） | 第2回（今回） |
| モデルの構造による誤差 | 現象に対する仮定が現実と異なること | 直接には減らない | 実際には変化し得る人口増加率を全期間で一定と仮定したこと | 第3回・第4回 |
| 観測の誤差 | 測定・集計・記録の不確かさ | 直接には減らない | 人口の調査・推計に伴う把握漏れや推計の不確かさ | 第12回 |
| パラメタ推定の誤差 | 有限かつ不確かなデータからパラメタを決めること | 固定した推定値の不確かさは減らない | 2時点の人口に誤差があれば，それらから算出する $r$ にも影響すること | 第7回・第12回 |

- 数値計算の設定変更：直接改善する対象は数値解法の誤差．
- 他の要因との関係：

  - パラメタ推定に数値解を使う場合：数値誤差が推定値にも影響する．
  - 観測値を初期値に使う場合：観測の不確かさが解に伝わる．

- 人口の例：

  - 数値解と解析解の差：出力時刻上で最大約0.6万人．
  - 解析解と2020年の観測値の差：約6600万人．
  - 比較結果：約4桁の差があり，数値誤差だけでは残差を説明できない．
  - 検討対象：モデルの仮定，推定期間，観測の定義．残差の全てをモデル構造の誤差と断定することはできない．

### Euler法の誤差と出力値からの読み取り

- 局所誤差と大域誤差：評価する範囲の違い．別々に加算する誤差成分ではない．
- 打ち切り誤差の評価条件：厳密な演算，十分滑らかな解，$x$ に関するLipschitz条件，固定した有限区間．
- 読み取りの誤差：数値解の出力から半減期などを求める際に，別途生じる誤差．

| 誤差 | 意味 | 大きさの目安 | 今回の例 |
| --- | --- | --- | --- |
| 局所打ち切り誤差 | 厳密な値から1ステップだけ進めたときに生じる誤差 | Euler法で $O(h^2)$ | 手計算の1ステップ目 $100 \to 120$（解析解は $122.14$） |
| 大域打ち切り誤差 | 初期時刻から更新を繰り返した近似値と厳密解との差．局所誤差の伝播を含む | Euler法で $O(h)$ | $h$ を1/10にすると $x(10)$ の誤差も約1/10になる |
| 丸め誤差 | 数値の表現や演算結果を有限精度で丸めること | 倍精度・最近接丸めの基本演算では，正規化数の範囲で相対誤差の上限は約 $1.1\times10^{-16}$ | ステップ数を増やすと，丸め誤差の累積が無視できなくなる場合がある |
| 読み取りの誤差 | しきい値を通過する時刻を，最初に条件を満たす出力時刻で代用すること | 単調な厳密解を標本化し，通過前後を含む場合は出力間隔未満．数値解では数値誤差も加わる | 半減期の読み取り値 $2.4$ 時間（解析解 $\ln 2 / k = 2.31$ 時間） |

- 局所打ち切り誤差の定義：本講義では，厳密解から1ステップ進めた値と厳密解との差そのもの．文献によっては $h$ で割った量を指すため，次数の比較には定義の確認が必要．
- 出力時刻と精度：出力時刻の間の値は補間でも評価できる．`t_eval`の間隔が数値解そのものの精度を決めるわけではない．
- 刻み幅を小さくした場合：

  - 打ち切り誤差：十分滑らかな解を安定に計算する範囲では減少する．
  - 丸め誤差：演算回数が増え，累積の影響が無視できなくなる場合がある．累積の仕方は方程式や演算順序にも依存する．
  - 総誤差：単調に減少するとは限らない．

- `solve_ivp`の調整目的：局所誤差の推定値を許容範囲に収めること．打ち切り誤差と丸め誤差の合計の最小化ではない．
- 補遺2の内容：浮動小数点数，丸め誤差，桁落ちなど．

```{tip} 計算を精密にすれば現実に合う，は誤解である

- 仮定・データを見直す根拠：刻み幅や許容誤差を段階的に厳しくしても，結果の変化が観測値との差に比べて十分小さい場合．
- 観測値と一致する場合の注意：数値誤差とモデルの誤差が偶然打ち消し合う可能性もある．
- 数値解の確認方法：解析解との比較，刻み幅や許容誤差を変えた計算との比較．
- 第12回への接続：4種類の誤差について，評価方法を整理する．
```

## まとめ

  - 精度：十分滑らかな解とLipschitz条件のもとで，固定区間上の大域打ち切り誤差は $O(h)$．

## 補遺1：解の存在と一意性

- **存在**：初期値問題を満たす解が1つ以上あること．
- **一意性**：初期値問題を満たす解が1つ以下あること．
- 数値計算との関係：近似する対象が存在して一意に定まるとき，数値計算結果は元の微分方程式の解を十分近似できていると評価できる．

```{important} 定理（Picard–Lindelöfの定理）

$a,b>0$ とし，長方形領域

$$
D = \{(t, x) : |t - t_0| \le a,\ |x - x_0| \le b\}
$$

上の実数値関数 $f$ が連続で，$x$ に関してLipschitz連続であり，そのLipschitz定数は $t$ に依らないものとする．
このとき，ある $\alpha\in(0,a]$ が存在し，初期値問題

$$
\left\{
\begin{aligned}
    &\frac{dx}{dt} = f(t, x) \\
    &x(t_0) = x_0
\end{aligned}
\right.
$$

は区間 $I=[t_0-\alpha,t_0+\alpha]$ 上に，グラフが $D$ に含まれる解をただ1つもつ．

```

- $x$ に関してLipschitz連続であり，そのLipschitz定数は$t$に依らない：$t$ に依存しない定数 $L\ge0$ が存在し，任意の $(t,x_1),(t,x_2)\in D$ に対して次の不等式が成り立つこと．

$$
|f(t,x_1)-f(t,x_2)|\le L|x_1-x_2|
$$

- Lipschitz定数 $L$：$x$ の変化に対する $f$ の変化の割合の上限．一様であれば全ての $t$ に共通の値を用いる．
<!-- - 存在区間の具体的な選び方：$f$ の連続性と $D$ のコンパクト性から $M=\max_{(t,x)\in D}|f(t,x)|$ は有限であり，次の $\alpha$ を選べる．以下の証明でもこの値を用いる． -->
<!--

## 補遺2：浮動小数点数と数値誤差

- 数値誤差：計算手順の近似や有限精度の演算による，数学的な値と計算結果の差．個々の演算や特別な問題では0となる場合もある．
- 記号：真の値を $x$，計算値を $\tilde{x}$ とする．
- 誤差の表し方：

$$
\text{絶対誤差} = |\tilde{x} - x|,
\qquad
\text{相対誤差} = \frac{|\tilde{x} - x|}{|x|} \quad (x \neq 0)
$$

- 絶対誤差：元の量と同じ単位で誤差の大きさを評価する．
- 相対誤差：真の値に対する割合や，有効数字を評価する．$x=0$ では定義できない．
- 符号付き誤差：$\tilde{x}-x$．本文の表では過大評価・過小評価の区別に用いる．
- 以下の分類の注意点：独立した5種類ではない．桁落ち・情報落ちは丸め誤差の影響とも関係する．

| 誤差 | いつ生じるか | 原因 | 対策 |
| --- | --- | --- | --- |
| 打ち切り誤差 | 微分・積分・級数などを有限の計算で近似するとき | 離散化や級数の有限項への打ち切り | 刻み幅を小さくする，次数の高い解法を使う |
| 丸め誤差 | 入力値や演算結果を浮動小数点数に丸めるとき | 有限の有効桁数では一般の実数を正確に表せないこと | 安定な計算式を選ぶ，必要に応じて高精度の型を使う |
| 桁落ち | 近い値の差をとり，上位桁が相殺されるとき | 被減数・減数がもつ誤差が，差に対して相対的に大きくなること | 近い値の差を直接計算しない式や専用関数を使う |
| 情報落ち | 絶対値の大きく異なる2数を足すとき | 小さい数の寄与の一部または全部が丸めで失われること | 総和では演算順序を検討し，`math.fsum`などを使う |
| オーバーフロー／アンダーフロー | 結果の絶対値が大きすぎる／0に近すぎるとき | 表現範囲の制約．0近傍では非正規化数を使えても相対精度が低下し，さらに小さい値は0に丸められる | 変数のスケーリングや対数を用いた計算を検討する |

- 打ち切り誤差の要因：離散化や有限項での近似．
- 有限精度計算の誤差に影響する要因：解法，式の変形，変数の尺度，演算順序．
- 倍精度（`float64`）：正規化数では，省略された先頭の1を含め53ビットの有効桁．10進数でおよそ15〜16桁に相当する．
- 計算機イプシロン：1と，1より大きい最小の表現可能数との差．$\varepsilon=2^{-52}\approx2.2\times10^{-16}$．
- 丸め誤差の上限：最近接丸めの基本演算では，正規化数の範囲で相対誤差は $u=\varepsilon/2$ 以下．$\varepsilon$ とは区別する．
- 表現可能な数の間隔：値の大きさに依存する．0近傍の非正規化数では相対精度が低下する．
- 参照先：[NumPyの`finfo`ドキュメント](https://numpy.org/doc/stable/reference/generated/numpy.finfo.html)．

```python
import math

print(f"倍精度の計算機イプシロン: {np.finfo(float).eps:.3e}")

# 丸め誤差：10進数の0.1は2進数では有限桁で表せない
print("0.1 + 0.2 =", 0.1 + 0.2, " 0.3と等しいか:", 0.1 + 0.2 == 0.3)

# 桁落ち：加算時の丸め誤差が，差に対して相対的に大きくなる
print("(1 + 1e-12) - 1 =", (1.0 + 1e-12) - 1.0, " 真値 1e-12")

# 情報落ち：絶対値の大きく異なる2数を足すと小さい方が消える
print("1e16 + 1.0 - 1e16 =", 1e16 + 1.0 - 1e16, " 真値 1.0")

# 総和のアルゴリズムを比較する：0.1を100万回足す
terms = np.full(1_000_000, 0.1)
naive_total = 0.0
for value in terms:
    naive_total += float(value)
print("逐次加算:", naive_total, " math.fsum:", math.fsum(terms), " 真値 100000.0")

# 同じ値の組でも，加算順序で結果が変わる例
print("(1e16 - 1e16) + 1 =", (1e16 - 1e16) + 1.0)
print("1e16 + (-1e16 + 1) =", 1e16 + (-1e16 + 1.0))

# オーバーフロー：表せる最大値を超えると inf になる
print("表せる最大値:", np.finfo(float).max)
print("1e308 * 10 =", 1e308 * 10)
```

### 刻み幅を小さくしすぎると精度が落ちる

- 目的：差分商を使い，打ち切り誤差と桁落ちの影響を比較する．
- 計算対象：$e^t$ の $t=0$ における微分係数．真値は1．
- 近似式：$(e^h-e^0)/h$．刻み幅 $h$ を段階的に小さくする．

```python
print(f"{'h':>8} {'近似値':>16} {'絶対誤差':>12}")
for h in [1e-1, 1e-2, 1e-4, 1e-6, 1e-8, 1e-10, 1e-12, 1e-14, 1e-16]:
    derivative = (np.exp(0.0 + h) - np.exp(0.0)) / h
    print(f"{h:8.0e} {derivative:16.12f} {abs(derivative - 1.0):12.3e}")
```

- `1e-8`：$1\times10^{-8}$ という数の表記．`np.exp`の略ではない．
- `:12.3e`：表示幅12文字，小数点以下3桁の指数表記で表示する指定．計算値自体は変えない．

- 打ち切り誤差：$(e^h-1)/h=1+h/2+O(h^2)$ より，丸め誤差が十分小さい範囲では $h$ にほぼ比例する．
- 丸め誤差の影響：$e^h$ の評価に $O(u)$ の誤差があれば，$h$ で割った後は $O(u/h)$．$h$ が小さいほど影響が大きくなる．
- 桁落ち：$e^h$ と $e^0$ が近づくほど，差の有効桁数が失われる．
- 計算結果の例：

  - $h=10^{-14}$：$h=10^{-4}$ より大きい誤差が生じ得る．
  - $h=10^{-16}$：$e^h$ と $e^0$ が同じ浮動小数点数となり，近似値は0．
  - 環境への依存：細かい数値や誤差が最小になる位置は，実行環境でも変わる．

- 刻み幅の目安：誤差を $C_1h+C_2u/h$ と見積もると，両項が同程度になる $h=O(\sqrt{u})$，約 $10^{-8}$ 付近．実際の誤差が前後で単調に変わる保証はない．
- 精度低下を抑える計算式：`np.expm1(h) / h`．$e^h-1$ を直接計算する場合と比較する．
- Euler法との違い：通常は $f(t,x)$ を直接評価し，この差分商は計算しない．上の刻み幅の目安をそのまま適用しないこと．
- 刻み幅の選び方：

  1. 要求精度を決める．
  2. 複数の刻み幅での結果を比較する．
  3. 利用可能なら解析解や別の安定な計算法と比較する．結果が変わらなくなるだけでは，正確さの保証にならない．

- 参照先：[NumPyの`expm1`ドキュメント](https://numpy.org/doc/stable/reference/generated/numpy.expm1.html)．

````{note} 発展問題1：Runge–Kutta法の導出

- Euler法：区間始点の傾き $f(t_k,x_k)$ だけを使う．
- 改善の方針：区間途中の傾きも使い，同じ刻み幅での精度を上げる．
- 2次のRunge–Kutta法（中点法）：次の2段階の計算を用いる．

$$
\left\{
\begin{aligned}
k_1 &= f(t_k,\ x_k) \\
k_2 &= f\!\left(t_k + \tfrac{h}{2},\ x_k + \tfrac{h}{2}\,k_1\right) \\
x_{k+1} &= x_k + h\,k_2
\end{aligned}
\right.
$$

- $k_1$：始点の傾き．中点での状態 $x_k+(h/2)k_1$ の予測に使う．
- $k_2$：予測した中点での傾き．$x_{k+1}=x_k+hk_2$ の更新に使う．

1. 局所誤差を調べるため，この設問では $x_k=x(t_k)$ とおき，$f$ と解が必要な回数だけ連続微分可能であると仮定する．$x(t_k + h)$ を $h$ について2次までTaylor展開し，$x'' = f_t + f_x\,f$ を使って
   $x(t_k + h) = x_k + h f + \frac{h^2}{2}\left(f_t + f_x f\right) + O(h^3)$
   となることを示す（右辺の $f$ とその偏導関数は $(t_k, x_k)$ での値とする）．
2. $k_2$ を2変数のTaylor展開で $h$ の1次まで展開し，$x_{k+1}$ が1の展開式の $h^2$ の項まで一致し，残差が $O(h^3)$ であることを確かめる．これは局所打ち切り誤差が $O(h^3)$ であることを示す．さらにLipschitz条件のもとで誤差の伝播を評価すると，固定した有限区間での大域誤差は $O(h^2)$ となる．
3. 本文の`euler`関数にならって`rk2(rhs, t_span, x0, h, args=())`を実装する．
4. $x' = 0.2\,x$，$x(0) = 100$，計算区間 $0\le t\le10$ について，$h = 1, 0.5, 0.1, 0.01$ でEuler法とRK2の $t = 10$ における絶対誤差を求め，`ax.loglog`で両対数グラフに描く．
5. 両対数グラフの傾きが，Euler法で約1，RK2で約2になることを確かめる．この傾きが収束次数に対応する理由を説明する．
6. `solve_ivp`が既定で使うRK45はさらに高次の方法である．同じ問題でRK45の絶対誤差と`sol.nfev`を調べ，同程度の精度を出すのにRK2が何ステップ必要かと比べる．右辺の評価回数として比較する場合は，RK2では1ステップにつき2回評価することに注意する．
````

### Euler法の不安定性

- 計算条件：$x'=-kx$，$k>0$，$x(0)>0$，一定の刻み幅 $h>0$．
- 更新式：$x_{k+1}=(1-hk)x_k$．
- 不安定となる条件：$hk>2$ なら $|1-hk|>1$．符号が交互に変わり，絶対値が増大する．
- 解析解との違い：解析解は単調に減衰するが，不安定な数値解は発散する．

````{dropdown} 発展演習：Euler法の不安定性

```python
k = 2.0
x0_decay = 100.0
t_span_decay = (0.0, 10.0)

fig, ax = plt.subplots(figsize=(7, 4))
t_fine = np.linspace(0.0, 10.0, 201)
ax.plot(t_fine, x0_decay * np.exp(-k * t_fine), color="black", label="analytical solution")
for h in [0.4, 0.9, 1.2]:
    t, x = euler(decay_rhs, t_span_decay, x0_decay, h, args=(k,))
    ax.plot(t, x, marker="o", markersize=3, linestyle="--", label=f"Euler, h = {h} (hk = {h * k:.1f})")
ax.set_title("Euler method for dx/dt = -2 x with large step sizes")
ax.set_xlabel("Time [arbitrary unit]")
ax.set_ylabel("x [arbitrary unit]")
ax.set_ylim(-300, 300)
ax.grid(True)
ax.legend()
fig.tight_layout()
fig.savefig(FIGURE_DIR / "euler_instability.png", dpi=150)
plt.show()
```

1. $0<hk<1$，$1<hk<2$，$hk>2$ の3つの場合で数値解の振舞いがどう違うかを説明する．境界の $hk=1$ と $hk=2$ についても更新式から確認する．最後に刻み幅を短くするステップでは，$h$ をその実際の刻み幅に置き換えて考える．
2. 同じ問題を`solve_ivp`で解き，解析解との絶対誤差を評価する．
3. 減衰が速い（$k$ が大きい）現象ほど，Euler法では小さい刻み幅が必要になる理由を説明する．
````

- 安定性の確認：刻み幅を選ぶ際は，解析解の挙動を数値解が再現できるかに注意する．
- `solve_ivp`でも必要な確認：計算の成功・失敗，許容誤差を変更したときの結果の変化．

````{note} 発展問題2：後退Euler法と数値的安定性

- 前進Euler法：始点の傾きを使用．上の減衰モデルでは $hk>2$ で発散する．
- 後退Euler法（陰的Euler法）：終点の傾きを使う次の更新式．

$$
x_{k+1} = x_k + h\,f(t_{k+1},\ x_{k+1})
$$

- 陰的な方法：次の時刻の未知値 $x_{k+1}$ を右辺にも含む更新式．
- 各ステップの処理：一般には $x_{k+1}$ に関する代数方程式を解く．計算量は求解方法にも依存する．

1. $f(t, x) = -k\,x$ の場合に上の式を $x_{k+1}$ について解き，$x_{k+1} = \dfrac{x_k}{1 + h k}$ となることを示す．
2. 任意の一定の刻み幅 $h > 0$，$k > 0$ に対して $0 < \dfrac{1}{1 + hk} < 1$ であることから，初期値が正なら数値解が単調に減少して0に近づくことを示す．前進Euler法の増幅率 $1 - hk$ と比べ，どこが違うかを述べる．
3. 後退Euler法を実装し，$x' = -2x$，$x(0) = 100$，計算区間0〜10について $h = 0.4,\ 0.9,\ 1.2$ で計算して，上の図と並べて描く．
4. 後退Euler法は安定だが，大域誤差は前進Euler法と同じ $O(h)$ である．$h = 1.2$ での解析解との絶対誤差を求め，数値解の安定性と近似精度が別であることを確認する．
5. $k$ を大きくし，`solve_ivp`のRK45と`method="Radau"`，`method="BDF"`を比較する．

   - 比較条件：同じ許容誤差・計算区間．
   - 比較項目：解析解との絶対誤差，`sol.nfev`．
   - 硬い問題（stiff problem）：精度のために必要な刻み幅よりも，陽的解法の安定性のために著しく小さい刻み幅が必要な問題．
   - 典型例：速く減衰する成分と遅い成分の共存．単一の減衰モデルでも，急減後の長い区間の計算で同様の制約が現れる．
   - 計算費用の注意：陰的解法には行列の分解などもあり，`sol.nfev`だけでは全費用を比較できない．
````
