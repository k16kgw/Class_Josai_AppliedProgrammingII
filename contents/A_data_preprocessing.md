```{tip} 前処理の目的
前処理は，見た目の整った表を作る作業ではない．元データの意味を保ったまま，研究質問と数理モデルに対応する観測値を，Pythonで検証可能な表へ変換する作業である．
```

## B．どのデータにも共通する前処理の手続き

### 前処理の全体像

データ形式や提供機関が異なっても，基本的な手続きは共通している．

```{mermaid}
flowchart LR
    A["研究質問を決める"] --> B["出典と利用条件を確認する"]
    B --> C["元データをrawに保存する"]
    C --> D["表の構造と注記を確認する"]
    D --> E["必要な行と列を選ぶ"]
    E --> F["型・日時・単位をそろえる"]
    F --> G["欠損・記号・重複を処理する"]
    G --> H["必要なら表を結合・変形する"]
    H --> I["件数・期間・値を検証する"]
    I --> J["processedに保存する"]
    J --> K["処理内容を記録する"]
```

### 研究質問から必要な観測値を決める

最初に「入手できる列をすべて使う」のではなく，研究質問とモデルから必要な観測値を逆算する．

例えば，ダムの貯水量変化を調べるなら，少なくとも次の対応を考える．

| モデル上の役割 | 必要なデータの例 |
| --- | --- |
| 状態変数と比較する観測量 | 貯水量または貯水位 |
| 外部入力 | 流入量，降水量 |
| 外部出力 | 放流量，取水量 |
| 時間 | 観測日または観測時刻 |

モデルに使わない列は削除してよいが，後から意味を確認できるよう，元ファイルは残す．

### 出典，利用条件，注記を先に読む

ダウンロード前後に，次の情報を記録する．

| 項目 | 記録する内容 |
| --- | --- |
| 提供機関 | 省庁，自治体，研究機関など |
| データ名 | 統計表やデータセットの正式名称 |
| URL | データを取得したページまたはAPI |
| 取得日 | ファイルを取得した年月日 |
| 利用条件 | 規約やライセンス，必要な出典表記 |
| 観測の定義 | 誰を，いつ，どのように測った値か |
| 注意事項 | 暫定値，補正値，品質記号，制度変更など |

同じ「人数」でも，国勢調査人口，推計人口，報告日別陽性者数では意味が異なる．列名だけで判断せず，提供元の注記を読む．

### 元データを変更せず保存する

データは少なくとも`raw`と`processed`に分ける．

```text
report_project/
├── data/
│   ├── raw/          # ダウンロードした元ファイルを変更せず保存
│   └── processed/    # 前処理後の分析用ファイル
├── src/
│   └── prepare_data.py
├── notebooks/
└── data_sources.md
```

元ファイルをExcelで直接編集して上書きすると，どの値を変更したか確認できなくなる．列の選択，値の置換，表の結合はPythonコードで実行し，同じ元ファイルから同じ処理済みファイルを再生成できるようにする．

### 読み込み直後に表の構造を確認する

読み込み後，値を加工する前に，行数，列名，データ型，欠損，先頭と末尾を確認する．

```python
from pathlib import Path

import pandas as pd

RAW_DIR = Path("../data/raw")

data = pd.read_csv(RAW_DIR / "original.csv")

print("行数・列数:", data.shape)
print("列名:", data.columns.tolist())
print(data.dtypes)
print("欠損数:")
print(data.isna().sum())
display(data.head())
display(data.tail())
```

Excelでは，表題，単位，注記が表の上部にあり，列名が複数行になっていることがある．その場合は`pd.read_excel()`の`sheet_name`，`header`，`skiprows`を調整する．まず`header=None`で読み，どの行から表が始まるか確認するとよい．

### 分析単位を1行にそろえる

前処理後の表では，「1行が何を表すか」を一文で説明できるようにする．

- 人口データ：1行が1年の日本の総人口
- ダムデータ：1行が1日の浦山ダムの観測値
- 訪日外客数：1行が1か月の訪日外客総数
- 感染症データ：1行が1報告日の地域別新規陽性者数

年が列方向に並ぶ表や，1つのセルに複数の値が入る表は，必要に応じて長形式へ変換する．

```python
long_data = wide_data.melt(
    id_vars=["項目"],
    var_name="year",
    value_name="value",
)
```

### 列名とデータ型をそろえる

列名は短く，一貫した名前にする．授業用データでは，コード中の日本語フォントや環境差を避けるため英語の`snake_case`へ変更した．ただし，元の列名との対応表を記録する．

```python
data = data.rename(
    columns={
        "年月日": "date",
        "日平均流入量": "inflow_m3s",
    }
)

data["date"] = pd.to_datetime(data["date"], errors="coerce")
```

`errors="coerce"`は変換できない値を欠損値にする．便利である一方，記号や入力ミスが黙って欠損になるため，変換前後の欠損数を比較する．

```python
raw_inflow = data["inflow_m3s"].copy()
missing_before = raw_inflow.isna().sum()
data["inflow_m3s"] = pd.to_numeric(raw_inflow, errors="coerce")
missing_after = data["inflow_m3s"].isna().sum()

print("数値変換によって増えた欠損:", missing_after - missing_before)
```

### 欠損値と特殊記号を区別する

空欄，`-`，`--`，`x`などがすべて欠損を表すとは限らない．例えば気象庁の`--`は「現象なし」を表し，降水量では0として扱える．一方，資料不足値は，本当の値が分からないため0に置き換えてはいけない．

欠損値への対応は，次のいずれかを理由とともに選ぶ．

| 対応 | 適する状況 | 注意点 |
| --- | --- | --- |
| 行を除く | 欠損が少なく，除いても時間の偏りが小さい | 時間間隔が不規則になる |
| 補間する | 状態が連続的に変化し，短い欠測である | 長期間の欠測や急変には不適切 |
| 0とする | 「観測されなかった」ことが0を意味する | 未観測と0を混同しない |
| 欠損のまま残す | 無理に値を作る根拠がない | 使用する関数が欠損に対応するか確認する |

### 時間軸を整える

日時を日時型へ変換し，時間順に並べ，重複と間隔を確認する．

```python
data["date"] = pd.to_datetime(data["date"], errors="raise")
data = data.sort_values("date").reset_index(drop=True)

print("日時の重複:", data["date"].duplicated().sum())
print("開始:", data["date"].min())
print("終了:", data["date"].max())
print("時間間隔:")
print(data["date"].diff().value_counts().head())
```

複数ファイルを結合すると，境界の年月が重複することがある．重複を機械的に削除する前に，値が同じか，どちらが改訂後の値かを確認する．

### 単位を確認してから変換する

単位変換は，元の列を残して新しい列を作ると確認しやすい．

```python
# m3/sを千m3/日に変換する例
data["inflow_1000m3_day"] = data["inflow_m3s"] * 86_400 / 1_000
```

変換式はコードだけでなく文章にも残す．異なる頻度のデータを結合する場合は，合計，平均，最大値のどれで集計するかを，変数の意味から決める．降水量は期間内の合計，気温は期間内の平均とすることが多いが，研究質問によって変わる．

### 保存前に検証する

前処理が完了したら，少なくとも次を確認する．

```python
assert data.columns.is_unique
assert not data["date"].duplicated().any()
assert data["date"].is_monotonic_increasing

print(data.shape)
print(data.isna().sum())
print(data.describe(include="all"))
```

さらに，提供元の表にある代表的な数値を数件照合する．合計値が公表されている場合は，前処理後の集計値と一致するか確認する．コードがエラーなく終了しても，誤った列を選んでいる可能性は残る．

### 処理済みデータと処理記録を保存する

```python
PROCESSED_DIR = Path("../data/processed")
PROCESSED_DIR.mkdir(parents=True, exist_ok=True)

data.to_csv(
    PROCESSED_DIR / "analysis_data.csv",
    index=False,
    encoding="utf-8",

```

`data_sources.md`には，取得方法だけでなく，次のように値が変わる操作をすべて記録する．

```markdown

- 欠損していた3日は除外した．
```

## C．日本の総人口データ

### 取得方法

[総務省統計局「人口推計の結果の概要」](https://www.stat.go.jp/data/jinsui/2.htm)の「長期時系列データ」から，次の2つのExcel表を取得した．

- 「我が国の推計人口（大正9年〜平成12年）」
- 「長期時系列データ（平成12年〜令和2年）」

2つの表を使用したのは，1920年から2020年までを同じ列構成のCSVにまとめるためである．

### 授業用データで行った処理

| 段階 | 処理内容 |
| --- | --- |
| 表の選択 | 各年10月1日現在の「男女計・総人口」に対応する系列を選択した |
| 行列の変形 | 年が横方向に並ぶ表を，1行1年の長形式へ変換した |
| 結合 | 1920〜2000年と2000〜2020年の表を縦に結合した |
| 重複の確認 | 両方に含まれる2000年について値と定義を確認し，1行だけ残した |
| 型の変換 | 年を整数，人口を数値へ変換した |
| 列名の変更 | `year`，`total_population_thousand`，`note`に統一した |
| 注記の保存 | 国勢調査人口，補正人口，臨時国勢調査人口などの区別を`note`へ残した |
| 並べ替え | 1920年から2020年まで昇順に並べた |

処理後は101行で，年の重複と人口の欠損がないことを確認した．`note`の空欄は人口の欠損ではなく，特別な注記がない推計人口を意味する．また，1945〜1971年の値には沖縄県が含まれないため，長期変化を解釈するときは注意する．

### 他のデータに応用できる点

- 複数の時期に分かれた統計表を結合するときは，境界年の重複と定義変更を確認する
- ワイド形式の公的統計表は，1行1観測の長形式へ変換する
- 数値だけでなく，国勢調査値，推計値，補正値などの属性を残す
- 統計の対象範囲が途中で変わっていないか確認する

## D．浦山ダムの日別データ

### 取得方法

[国土交通省「ダム諸量データベース」浦山ダム](https://mudam.nilim.go.jp/chronology/summary/114)の「貯水位、流入量及び放流量に関する年表」から，2015年から2023年までの年別CSVを取得した．この表の流入量と放流量は日平均値である．

### 授業用データで行った処理

| 段階 | 処理内容 |
| --- | --- |
| 文字コード | 年別CSVをShift_JISとして読み込んだ |
| 列の選択 | 年月日，日平均貯水位，日平均流入量，日平均放流量を選択した |
| 日付の変換 | 年月日を`date`へまとめ，日時型として解釈できる形にした |
| 数値の変換 | 単位や記号を除き，貯水位・流入量・放流量を数値へ変換した |
| 年別表の結合 | 9年分を縦に結合し，日付順に並べた |
| 列名の変更 | `water_level_m`，`inflow_m3s`，`outflow_m3s`に統一した |
| 検証 | 日付の重複，欠損，日付間隔を確認した |

処理後は2015年1月1日から2023年12月31日までの3287行で，日付の重複と欠損はない．

授業用CSVでは，貯水位を貯水量へ変換していない．貯水位と貯水量は別の物理量であり，変換には本来，ダム固有の水位容量曲線が必要である．講義中の線形換算や，m³/sから千m³/日への換算は，前処理ではなく数理モデルを計算する段階で行っている．

### 他のデータに応用できる点

- 年別・月別に分かれたファイルは，同じ列と単位にそろえてから結合する
- 文字コードがUTF-8とは限らないため，文字化けした場合はShift_JISなどを確認する
- 同じ名称に見える量でも，瞬時値，日平均値，日合計値を区別する
- 物理量の変換に追加の仮定が必要なら，単なる前処理として隠さず，モデル上の仮定として明示する

## E．秩父の日降水量データ

### 取得方法

[気象庁「過去の気象データ・ダウンロード」](https://www.data.jma.go.jp/risk/obsdl/)または[過去の気象データ検索](https://ds.data.jma.go.jp/obd/stats/etrn/view/daily_s1.php?prec_no=43&block_no=47641)で，地点「秩父」，項目「日降水量の合計」，期間2019年1月1日〜2023年12月31日を指定した．

大量のページへ自動的に繰り返しアクセスする方法は避け，提供されているダウンロード機能を使用する．

### 授業用データで行った処理

| 段階 | 処理内容 |
| --- | --- |
| 列の選択 | 年月日と日降水量の合計だけを選択した |
| 日付の変換 | 年，月，日を`date`へまとめた |
| 現象なし | `--`は気象庁の定義に従い0.0 mmとした |
| 品質記号 | `)`と`]`を数値から取り除き，数値部分を採用した |
| 数値の変換 | 日降水量を`precipitation_mm`という数値列にした |
| 結合と並べ替え | 月別の表を結合し，日付順に並べた |
| 検証 | 連続した日付，重複，欠損，負の降水量がないことを確認した |

処理後は2019年1月1日から2023年12月31日までの1826行である．`)`は準正常値，`]`は資料不足値を示す．授業用CSVでは講義を簡潔にするため記号を除いて数値を採用したが，最終レポートでは`quality`列を作り，品質情報を残す方が望ましい．特に資料不足値は通常の観測値と同等に扱わず，除外した場合と含めた場合で結果が変わるか確認する．記号の意味は[気象庁「値欄の記号の説明」](https://ds.data.jma.go.jp/obd/stats/data/mdrr/man/remark.html)で確認できる．

### 他のデータに応用できる点

- 記号を削除する前に，提供元の定義を確認する
- 「現象なし」「未観測」「資料不足」を別の状態として扱う
- 品質フラグは捨てず，値の列とは別の列に保存する
- 気象観測所の移転や測定方法の変更による不均質にも注意する

## F．訪日外客数の月次データ

### 取得方法

[日本政府観光局「訪日外客統計」](https://www.jnto.go.jp/statistics/data/visitors-statistics/)から，「国籍/月別 訪日外客数」のExcelファイルを取得した．このページでは，月別・年別の資料と，直近月の推計値・暫定値が公開されている．

### 授業用データで行った処理

| 段階 | 処理内容 |
| --- | --- |
| 表の選択 | 国籍別の内訳ではなく，訪日外客数の総数を選択した |
| 行列の変形 | 1月〜12月が列に並ぶ年別表を，1行1か月の長形式へ変換した |
| 数値の変換 | 桁区切りや注記記号を除き，人数を整数へ変換した |
| 列の分割 | 時点を`year`と`month`の2列で表した |
| 列名の変更 | 人数を`visitors`とした |
| 並べ替え | 2003年1月から時系列順に並べた |
| 検証 | 年と月の組に重複がないこと，月が1〜12の範囲であることを確認した |

処理後は2003年1月から2026年8月までの284行である．直近の値には推計値または暫定値が含まれる．授業用CSVでは系列種別の列を省略したが，改訂される可能性が分析に影響する場合は，`status`列に`estimated`，`provisional`，`confirmed`などを保存する．

### 他のデータに応用できる点

- 人が読むための年別Excelを，分析用の1行1時点の表へ変換する
- 総数と内訳を混在させず，分析対象を明確に選ぶ
- 推計値，暫定値，確定値を区別し，データ更新時に再現できるよう取得日を残す
- 年と月から日時列を作る場合は，各月の月初・月末・中央のどこに対応させたかを明示する

## G．カンジキウサギとカナダオオヤマネコの毛皮データ

### 取得方法

Rパッケージ[`tsibbledata`](https://github.com/tidyverts/tsibbledata)の`pelt`データを作成するために公開されている`data-raw/pelt/lynxhare.csv`を取得した．原典はHudson's Bay Companyの毛皮取引記録であり，MacLulich（1937）をもとにOdum（1953）が再編集した古典データである．

### 授業用データで行った処理

| 段階 | 処理内容 |
| --- | --- |
| 列の選択 | 年，カンジキウサギ毛皮数，カナダオオヤマネコ毛皮数を選択した |
| 列名の変更 | `year`，`hare_pelts_thousand`，`lynx_pelts_thousand`に統一した |
| 型の変換 | 年を整数，毛皮数を数値へ変換した |
| 単位の明示 | 毛皮数の単位が千枚であることを列名に含めた |
| 並べ替え | 1845年から1935年まで昇順に並べた |
| 検証 | 91年分について，年の重複と欠損がないことを確認した |

値の補間や平滑化は行っていない．毛皮取引数は野生動物の個体数そのものではない．講義では「取引数が個体数に比例する」という観測モデルの仮定を置く．この仮定は前処理によって事実になるものではなく，分析時に妥当性を議論する必要がある．

### 他のデータに応用できる点

- 二次配布されたデータでは，配布元だけでなく可能な限り原典までたどる
- 列名に単位を含めるか，データ辞書で単位を明示する
- 代理指標と本当に知りたい状態変数を区別する
- 平滑化や補間をしないという判断も，記録すべき前処理方針である

## H．新型コロナウイルス感染症の新規陽性者数

### 取得方法

[厚生労働省「オープンデータ」](https://www.mhlw.go.jp/stf/covid-19/open-data.html)から，新規陽性者数の推移の日別CSVを取得した．元データは，日付ごとに全国および都道府県の値が列方向に並ぶワイド形式である．

### 授業用データで行った処理

| 段階 | 処理内容 |
| --- | --- |
| 列の選択 | 日付，全国，埼玉県，東京都の4列を選択した |
| 列名の変更 | `date`，`new_cases_japan`，`new_cases_saitama`，`new_cases_tokyo`に統一した |
| 日付の変換 | 報告日を日時型として解釈できる形式にした |
| 数値の変換 | 新規陽性者数を整数へ変換した |
| 期間の選択 | 公開系列の2020年1月16日から2023年5月8日までを使用した |
| 並べ替え | 報告日の昇順に並べた |
| 検証 | 1209日分について，日付の重複と欠損がないことを確認した |

移動平均は前処理済みCSVには追加していない．第11回では，曜日による報告数の偏りを見やすくするため，分析時に7日間移動平均を計算する．元の観測値を残し，平滑化した列を別に作ることが重要である．

このデータの日付は感染日や発症日ではなく報告日である．また，集計方法や報告制度は期間中に変更されている．日付型への変換や列名の整理だけでは，このような定義上の変化は解決しないため，結果の解釈で扱う．

### 他のデータに応用できる点

- 多数の地域が列に並ぶワイド形式から，必要な地域を選ぶか，地域を行にした長形式へ変換する
- 元の観測値と移動平均などの派生値を別の列にする
- 日付が「発生日」「観測日」「報告日」のどれかを確認する
- 制度変更や集計方法の変更点を，時系列上の構造変化として記録する

## I．6種類のデータから得られる共通パターン

| 前処理上の問題 | 授業用データの例 | 自分のデータで確認すること |
| --- | --- | --- |
| 複数ファイルの結合 | 人口，ダム | 境界時点の重複，列名，単位，定義は同じか |
| ワイド形式から長形式への変換 | 人口，訪日外客数 | 1行が1観測になっているか |
| 特殊記号の解釈 | 降水量 | 0，欠損，現象なし，品質不足を区別したか |
| 暫定値・補正値 | 人口，訪日外客数 | 値の種類を列または注記に残したか |
| 文字コード | ダム | UTF-8，Shift_JISなどを確認したか |
| 観測頻度の統一 | ダム，降水量，訪日外客数 | 日次，月次，年次を混同していないか |
| 代理指標 | 毛皮数，新規陽性者数，貯水位 | 観測量とモデルの状態変数の関係を説明したか |
| 派生値の作成 | 移動平均，単位換算 | 元の列を残し，計算式を記録したか |
| 制度・対象範囲の変更 | 人口，新規陽性者数 | 時系列の途中で比較可能性が変わっていないか |

異なるデータに同じ前処理コードを機械的に適用するのではなく，この表から該当する問題を選び，提供元の定義と研究質問に合わせて判断する．

## J．再現可能な前処理スクリプトのひな形

次のひな形では，読み込み，確認，変換，検証，保存を関数に分けている．実際の列名と処理内容は自分のデータに合わせて変更する．

```python
from pathlib import Path

import pandas as pd

RAW_PATH = Path("data/raw/original.csv")
OUTPUT_PATH = Path("data/processed/analysis_data.csv")


def load_raw_data(path):
    """元データを読み込み，変更前の形を返す．"""
    return pd.read_csv(path)


def preprocess(raw_data):
    """研究質問に必要な列を選び，型と時間軸を整える．"""
    data = raw_data[["元の日付列", "元の値列"]].copy()
    data = data.rename(
        columns={
            "元の日付列": "date",
            "元の値列": "value",
        }
    )

    data["date"] = pd.to_datetime(data["date"], errors="raise")
    data["value"] = pd.to_numeric(data["value"], errors="coerce")
    data = data.sort_values("date").reset_index(drop=True)

    return data


def validate(data):
    """分析に必要な条件を満たすか確認する．"""
    assert data.columns.tolist() == ["date", "value"]
    assert not data["date"].isna().any()
    assert not data["date"].duplicated().any()
    assert data["date"].is_monotonic_increasing

    print("行数・列数:", data.shape)
    print("期間:", data["date"].min(), "〜", data["date"].max())
    print("欠損数:")
    print(data.isna().sum())
    print(data.describe(include="all"))


def main():
    raw_data = load_raw_data(RAW_PATH)
    print("元データ:", raw_data.shape)

    data = preprocess(raw_data)
    validate(data)

    OUTPUT_PATH.parent.mkdir(parents=True, exist_ok=True)
    data.to_csv(OUTPUT_PATH, index=False, encoding="utf-8")
    print("保存先:", OUTPUT_PATH)


if __name__ == "__main__":
    main()
```

スクリプトの中だけでは説明できない判断は，コメントと`data_sources.md`に残す．例えば，「欠損を補間した理由」「特定期間を除いた理由」「資料不足値を採用した理由」は，コードから自動的には分からない．

## K．最終レポートに記載する内容

最終レポートの「使用したデータと出典」と「データの前処理」には，少なくとも次を記載する．

### 使用したデータと出典

- 提供機関とデータの正式名称
- 取得元URLと取得日
- 利用条件と指定された出典表記
- 対象地域，対象期間，観測頻度，単位
- 観測値の定義と，モデルの状態変数との関係

### データの前処理

- 使用した元ファイルとシート
- 選択した行と列，除外した行と列
- 列名とデータ型の変更
- 欠損値，特殊記号，重複の扱い
- 単位換算，集計，補間，平滑化の方法
- 複数の表を結合したキーと結合方法
- 前処理後の行数，期間，欠損数
- 前処理が正しいことを確認した方法

```{note} 前処理の判断を説明する
「欠損を削除した」「月平均を計算した」とだけ書くのではなく，なぜその処理が研究質問とモデルに適しているかを書く．別の処理を選ぶと結果が変わり得る場合は，その影響も述べる．
```

## L．提出前の確認

- 元データを`raw`に変更せず保存したか
- 出典，URL，取得日，利用条件を記録したか
- 1行が何を表すか説明できるか
- 日付，地域，個体など，行を識別するキーに重複がないか
- 数値の0と欠損値を区別したか
- 品質記号，暫定値，補正値を確認したか
- 単位と観測頻度を確認したか
- 観測量とモデルの状態変数を混同していないか
- 前処理をPythonコードで再実行できるか
- 前処理後の行数，期間，欠損数を確認したか
- 提供元の代表値と照合したか
- 第三者が`data_sources.md`とコードから同じCSVを作れるか

この確認を終えてから，数理モデルの構築とパラメタ推定へ進む．
