# 講義ノートの執筆・改訂指針

第7回講義ノートの作成・査読で確認した事項を，別の題材や講義にも適用できる形で整理する．数式・コード・設問・解答例を，学生が順に読み，実行し，結果を説明できる一連の教材として設計する．

本書は，執筆時の判断基準と具体的な書き方を示す参照文書である．個別の講義の到達目標・既習事項・授業時間に合わせて適用する．プロジェクトの作業上の指示は[AGENTS.md](../AGENTS.md)を参照する．

## 1．学習内容と分量の設計

- **到達目標**：学生が説明・実装・比較・評価できることを，対象と操作を含めて記す．「理解する」だけで終えず，何ができれば到達したと判断するかを示す．
- **既習事項**：今回の計算に必要な内容を復習・準備にまとめる．説明は短くし，実行に必要なコードは再掲する．毎回共通の環境設定は，一つのコードブロックにまとめてよい．
- **新規事項**：既習の方法から変更する部分と，変更によって調べられることを明確にする．新しい関数や手法には，使用前に必要な説明を置く．
- **授業時間**：説明に加え，コードの入力・実行，図の確認，演習に必要な時間を見積もる．本筋から離れる数学的な補足や追加分析は，補足節・発展課題に配置する．
- **まとめ**：覚えて帰るべき判断基準や結果の解釈を少数に絞り，課題の前に置く．次回への接続も必要な一言にまとめる．

内容を残すか迷った場合は，到達目標，コードの実行，結果の解釈のどれに必要かを確認する．

## 2．説明の具体性と文章の構成

### 入力・処理・出力・評価対象の明示

説明では，何を与え，何を計算し，どのデータと比較するかを具体的に示す．比較する条件には，固定するものと変更するものを明記する．

| 説明の対象 | 明示する内容 |
| --- | --- |
| モデル | 入力，状態変数，仮定，計算する量 |
| データとの対応 | 観測量，単位，観測時刻，モデルの計算結果からの換算 |
| 手法の比較 | 共通にする条件，変更する手順，比較に使う尺度 |
| 結果の評価 | 評価用データ，指標，結果からいえること，成立する範囲 |

例えば「予測の性能ではない」と説明する代わりに，「観測された入力を与えたとき，同じ係数で別の期間の変化をどの程度再現できるかを評価する」と，実際に調べた内容を述べる．

数学的な成立条件や解釈の範囲を示すために否定表現が必要な場合は，理由と，代わりにいえることを添える．

### 説明の配置と強弱

- **段落**：一つの論点を短くまとめ，結論，根拠，注意点の役割を分ける．近接する箇所で同じ結論を繰り返さない．
- **箇条書き**：定義，役割，比較条件などの対応関係を示す．各項目を文として完結させ，共通の観点で並べる．
- **用語の定義**：`- **用語**：意味．`の形式を基本とする．変数の説明は，記号を先頭に置いて量と単位を示す．
- **表**：引数と役割，推定対象と固定値など，複数の対応を比較するときに使う．
- **強調**：要点や判断基準を選択的に強調する．長い段落全体や準備操作まで一律に強調しない．
- **見出し**：「式の導出」「推定結果の比較」などの体言止めとする．

標準的な用語を優先し，独自の説明用の呼称を標準的な手法名のように扱わない．「図」「この結果」「同じ方法」と書くときは，参照先が直前・直後で明確かを確かめ，離れた節にはリンクを付ける．

## 3．数式とモデルの正確性

- **記号の定義**：量・単位・添字の意味を初出時に示す．同じ記号を別の意味で使う場合は，改めて定義する．時刻の原点と初期条件の対応も明記する．
- **パラメタの区別**：推定する値，固定する値，探索の開始値を区別する．微分方程式の初期条件と，最適化を始めるパラメタの初期値も区別する．
- **数学と実装の対応**：コードの前に必要な式を示す．状態変数から観測量への換算がある場合は，その式と，初期値の設定に使う逆変換も示す．
- **誤差の定義**：残差の符号と単位を統一する．二乗和，平均二乗誤差，最適化関数が返す値などは，計算式と用途を対応させる．
- **成立条件**：正値性，定義域，初期値，パラメタの制約を確認する．探索範囲には，モデルの仮定から定まる条件と計算上設定した範囲を区別して示す．
- **式変形**：微分記号を独立した数のように扱う操作を避け，連鎖律や積分によって正確に記述する．

定理は簡潔な文章と数式で述べ，用語の定義や補足説明は主張の外に置く．導出の補足は，主張，段階ごとの証明，初期条件・特殊例の確認を基本とする．

結果の解釈では，次の三つを分けて記す．

| 観点 | 確認すること |
| --- | --- |
| 計算手法 | 探索の開始値・範囲・停止結果と，得られた目的関数値 |
| データへの適合・適用 | 推定に使ったデータへの当てはまりと，係数を固定した未使用データへの適用結果 |
| 現象の説明 | モデルの仮定，データの作成方法，推定値を現実の量として解釈する根拠 |

特に，推定に使うデータ，初期条件に使うデータ，外部入力として使うデータ，評価に使うデータを明示する．この区別によって，評価している予測・再現の意味が定まる．

## 4．コードの提示と補足

### 処理単位での分割

コードは，データの読み込み，内容の確認，配列の準備，計算，結果の表示，描画などの役割ごとに分割する．各ブロックの直前には，何をするコードかを一言以上で説明する．

基本の配置は，次の順序とする．

1. 実施する処理の説明
2. コード
3. 該当するコードの補足
4. 実行した出力・図
5. 結果の解釈

計算と描画は別ブロックにし，上から順に実行できる依存関係を保つ．複数回使う処理では，変数名と処理順序をできる限り統一する．対象を切り替えても保持する値には，固定した参照値であることが分かる名前を付ける．

### 初出の関数と変数の説明

- **関数・API**：何をするかに加え，渡す引数，順序，型・形状，戻り値を使用前に示す．結果オブジェクトは，後で参照する項目の意味も説明する．
- **略語**：添字や属性名の略語は，初出時に意味を短く示す．
- **物理量**：配列を作る行には，量の名称と単位をコメントで添える．時刻には原点も示す．
- **描画技法**：初出の引数や表示方法は，直後の「コードの補足」で説明する．

例えば，次のように変数と物理量を対応させる．

```python
t_obs = data["elapsed_days"].values  # 時刻 [日]（観測開始日からの経過日数）
q_in = data["inflow"].values        # 流入量 [千m^3/日]
h_obs = data["water_level"].values  # 観測水位 [m]
```

コードは学習段階に合った構文で書く．既習事項だけで表せる処理には，説明のために必要な範囲で変数を設け，長いメソッドの連鎖を分ける．補足は使用している指定の意味に絞り，未使用の機能との対比を増やさない．

## 5．演習・課題の設計

### 本文からの接続

- **演習**：本文のコードを再構成し，条件や対象を変更して新しい結果を得る問題とする．関連する本文の末尾に置き，講義内で通し番号を付ける．
- **課題**：本文や既習のコードを組み合わせ，状況に応じて変更して実施する問題とする．記述問題は学習目標に必要な数に絞る．
- **発展課題**：追加の仮定や考察に取り組む問題とし，必要な準備・定義を先に示す．設問部分を本文から明確に区切る．

本文から何を変えるかを設問で具体的に示す．例えば，対象期間，推定に使うデータ，固定する係数などの違いを明示する．変更箇所を学生に判断させる場合は，変数名や行番号を答えとして与える代わりに，実現する内容を意味で記述する．

### 解答単位の明確化

- **一つの番号**：一つの成果物を求める．計算結果の出力，図の作成，文章による考察がそれぞれ必要なら，番号を分ける．複数の数値を含む一つの比較表や，上下のパネルを持つ一つの図は，一つの成果物として扱える．
- **解答指示**：「出力せよ」「記せ」「説明せよ」などの命令形を使い，何をどこへ解答するかを明示する．
- **解答範囲**：考察に分量の目安を付ける場合は，「2〜3文程度」のように示す．図や数値から判断させる問題には，根拠として使う情報を指定する．
- **強調**：赤字は最終的な解答指示の短い一箇所に絞る．

補完コードの完成後にも作業が必要なら，「本文の描画コードを使って図を出力せよ」のように続く処理を明記する．追加の成果物を求める場合は別の設問にする．

### 補完コードの変数名の固定

代入先の変数名をあらかじめ示し，右辺を補完させる．後続のコードで使う名前，ループ変数，推定結果の保存先も固定する．

```python
train_mask = 【訓練期間を選ぶ条件】
t_train = 【訓練期間の時刻の配列】
y_train = 【訓練期間の観測値の配列】
result_train = least_squares(【訓練データで推定するための引数】)
```

補完する範囲は，配列の抽出，関数呼び出し，引数の組など，意味のある単位にまとめる．細かな空欄の連続を避けつつ，式の選択やデータの対応を学生が考える余地を残す．

## 6．解答例と提出方法

- **解答例の構成**：本文のコードを大部分再利用し，設問に必要な条件・式・対象データだけを変更する．解答例だけに新しいループ・関数・データ構造を追加する場合は，その必要性と使い方を先に説明する．
- **解説**：なぜそのコードになるかを，本文の式や手順との対応で短く説明する．
- **出力**：コードを実行した結果や図を掲載する．掲載する数値・図・文章が同じ条件に基づいていることを確認する．
- **変更箇所の強調**：条件，式，探索範囲，処理手順，表示尺度など，本質的に変えた部分を強調する．変数名・インデント・凡例などの表記だけの変更は，強調の対象から外す．
- **設問との対応**：設問番号，解答例の番号，READMEの解答欄を揃える．設問を削除・分割した場合は，参照や解答例もまとめて改訂する．

Notebookにはコード・計算結果・図を出力し，READMEには設問で求めた少量の数値や短い考察を記入させる．図を示す欄には「（Notebookに図を出力）」と記し，ファイル内の場所の転記を求めない．多数の数値の傾向はグラフで比較する．

READMEへの記入指示は演習・課題にまとめる．提出先・期限・提出物を明示し，設問と提出物の対応を確認する．

## 7．図と数式の表示

- **比較図**：比較する条件，単位，期間，残差の符号を明示する．同じ条件・同じ量は，パネル間でも色を揃える．
- **表示方法**：尺度や表示範囲の変更は，読み取る内容との関係を説明する．改善の必要性を学ぶ場面では，基本の表示を確認してから変更を示す．
- **説明図**：入力から計算結果までの関係が複数ある場合は，処理とデータを箱，受け渡す量を矢印で示す．
- **文字と数式**：日本語のラベルは通常フォント，変数・式は数式モードにする．箱の見出しと式を別行に配置し，日本語を数式の一部として組版しない．
- **日本語表示**：描画環境に合わせてフォントを設定する．タイトル・軸名は日本語とし，変数名を軸名として使う場合はそのまま示す．
- **配色**：説明図はメインカラーと強調カラーの2色を基本とする．白・黒・グレーを文字，背景，罫線に使う．

図中の文字サイズ，折り返し，矢印の向き，数式の添字・分数・改行は，実際の描画結果を見て確認する．

## 8．MySTでの運用

### 囲みと解答例の公開状態

| 記法 | 用途 |
| --- | --- |
| `{note}` | 演習と自主学習用の発展課題の設問 |
| `{warning}` | 提出課題の設問 |
| `{tip}` | 仮定，説明，注意点などの補足 |
| `{dropdown}` | 長くなるコードの補足などの折りたたみ |
| `{visible-answer}` | 公開する解答例．折りたたんで表示 |
| `{hidden-answer}` | ビルド結果から本文を除外する解答例 |

`visible-answer`と`hidden-answer`は，本プロジェクトのプラグインによる記法である．公開状態の変更はタグで管理し，改訂時は既存の公開状態を維持する．公開・非公開の運用は[README](../README.md#解答例の公開非公開)を参照する．

### 構文と参照の確認

- **コードの補足**：3行以上になる場合はdropdownにまとめ，該当するコードの直後に置く．dropdown内の区分には太字の小見出しを使う．
- **フェンス**：開始と終了を対で確認し，外側のバッククォートを内側より長くする．コードの分割・結合時も，同じ確認を行う．
- **強調**：`**…**`の内側に丸括弧・かぎ括弧や前後の空白を入れない．用語に続く数式や括弧書きは強調の外に置く．
- **数式**：本文中の `$…$` の前後に半角スペースを置く．
- **変更箇所の表示**：`{code-block}`の`:emphasize-lines:`など，実際に強調される記法を用いる．行番号が対象コードに対応するか確認する．
- **節へのリンク**：必要に応じて明示的なラベルを付け，ビルド後の参照先を確認する．
- **データ配布**：ダウンロード用のリンクには`{download}`を使い，配信されるファイルと参照先を確認する．

## 9．完成時の検証

検証は，原稿の読み直し，コードの実行，配信される出力の確認を組み合わせて行う．

| 確認対象 | 検証方法 |
| --- | --- |
| 数式・用語 | 記号，単位，添字，成立条件，コードとの対応を確認する |
| 実行順序 | 初期状態から本文を実行し，各演習・課題も直前までの準備で実施できるか確認する |
| 補完コード | 指定された変数名で空欄を埋め，後続の計算・描画につながるか確認する |
| 数値・図 | 実行した出力と掲載値・図を照合し，本文の解釈も確かめる |
| 設問・提出物 | 番号，成果物，READMEの欄，提出先・期限を照合する |
| ビルド | ビルドを実行し，警告とリンク・参照の解決結果を確認する |
| 実際の表示 | 強調，コードの言語，折りたたみ，図中の数式，改行を確認する |

ビルド成功に加え，生成された出力で記法が意図した要素になっていることを確認する．特に図のフォントや数式の配置は，ブラウザで実際に表示する．実行環境で末尾の数値や評価回数が変わる場合は，変動する範囲を説明し，主要な結論との整合性を確かめる．

改訂時は，変更箇所に依存するコード・出力・解答例・参照を確認する．対象外の講義の一括改訂は，依頼の範囲に合わせて行う．
