### なぜ数値的に解く必要があるのか

微分方程式の中には指数関数などを用いて解を明示的な数式で表せるものがあり，解析的な計算によって得られる解を**解析解**と呼ぶ．
$x' = rx$ の解析解は $x(t) = x_0 e^{rt}$ である．
しかし，仮定を少し現実的にするだけで，解の式は簡単には求まらなくなる．

| 仮定 | 微分方程式 | 解析的な計算の方法と制約（初期時刻は0） |
| --- | --- | --- |
| 変化率が現在量に比例する | $x' = rx$ | $x_0 e^{rt}$ |
| 一人あたりの増加率が人口に対して線形に減少する（第4回） | $x' = rx(1 - x/K)$ | 変数分離により解析解を求められる |
| 流入量と放流量を観測データで与える（第6回） | $V' = Q_{\mathrm{in}}(t) - Q_{\mathrm{out}}(t)$ | 入力を補間し，その時間積分を計算する |
| 捕食によって2つの個体群が相互作用する（第10回） | $x' = ax - bxy$，$y' = -cy + dxy$ | 一般の初期条件に対して，時間の関数としての解を初等関数で表すことは困難である |

その処方箋として，離散的な時刻における解の近似値である**数値解**を計算し，状態変数の時間変化を調べる．
この手順なら，観測データを入力とするモデルや連立微分方程式にも同じやり方で対応できる．

## 初期値問題

### 定義

時間 $t$ とともに変わる状態変数 $x(t)$ について，

$$
\left\{
\begin{aligned}
\frac{dx}{dt} &= f(t, x) \\
x(t_0) &= x_0
\end{aligned}
\right.
$$

をともに満たす関数 $x(t)$ を求める問題を**初期値問題**と呼ぶ．
1つ目の式が微分方程式，2つ目の式が初期条件である．

- $f(t, x)$ は，時刻 $t$ に状態が $x$ であるときの変化率を与える関数である．状態の変化に関する仮定を $f$ の関数形で表す
- $x_0$ は，初期時刻 $t_0$ における状態変数の値である

微分方程式だけでは解は1つに決まらない．
$x' = rx$ を満たす関数は $x_0$ の値ごとに無数にある．
この方程式では，初期条件を与えると解が一意に定まる．
微分方程式は各時刻・状態における変化率を規定し，初期条件は特定の時刻における状態を指定する．
一般の $f$ について解が存在して1つに定まるための十分条件は，補遺1で述べる．

### 例：指数的な増加と減衰

$f(t, x) = rx$ の場合，初期値問題の解は

$$
x(t) = x_0\,e^{r(t - t_0)}
$$

である．
$x_0>0$ のとき，$r>0$ なら増加，$r<0$ なら0への減衰，$r=0$ なら一定値を表す．
減衰の例には，薬物の血中濃度，放射性物質の量，室温との温度差などがある．

````{dropdown} 補足：解析解が初期値問題を満たすことの確認

$x(t) = x_0 e^{r(t - t_0)}$ を $t$ で微分すると，

$$
\frac{dx}{dt} = x_0\,r\,e^{r(t - t_0)} = r\,x(t)
$$

となり，微分方程式を満たす．
また $t = t_0$ を代入すると $x(t_0) = x_0 e^{0} = x_0$ で，初期条件も満たす．

この講義では，解析解が分かる場合は，数値解が正しく計算できているかを確かめる基準として使う．
````

この解析解をPythonの関数として用意しておく．
この関数の値を基準として数値解の誤差を評価する．以下では数値解から解析解を引いた符号付きの誤差と，その絶対値を区別する．

```python
def exponential_solution(t, x0, r, t0=0.0):
    """dx/dt = r x, x(t0) = x0 の解析解 x0 * exp(r (t - t0)) を返す．"""
    return x0 * np.exp(r * (t - t0))
```

## Euler法：解の一次近似による時間発展の計算

### 導出

微分の定義から，刻み幅 $h$ が小さいとき

$$
x'(t) \approx \frac{x(t + h) - x(t)}{h}
$$

である．
これを $x(t + h)$ について解くと，

$$
x(t + h) \approx x(t) + h\,x'(t) = x(t) + h\,f(t, x(t))
$$

となる．
右辺は，時刻 $t$ の値と傾きだけから計算できる．
区間内の変化率を区間始点の値で近似し，その値と刻み幅の積を現在の値に加える操作である．

時刻を $t_k = t_0 + kh$，そのときの近似値を $x_k$ と書くと，**Euler法**は次の繰り返しになる．

$$
x_{k+1} = x_k + h\,f(t_k, x_k),
\qquad k = 0, 1, 2, \ldots
$$

初期値 $x_0$ から更新式を逐次適用し，各時刻の近似値を計算する．
第1回の漸化式 $x_{k+1} = x_k + r x_k$ は，$f(t, x) = rx$，$h = 1$ の場合にほかならない．

```{tip} Euler法の誤差はどこから来るか
Euler法は，$t_k$ から $t_{k+1}$ までの間，傾きが $f(t_k, x_k)$ のまま変わらないと見なしている．
この近似による誤差が各ステップで生じ，蓄積していく．刻み幅と誤差の関係は「誤差の分類」で整理する．
なお $O(h^p)$ は，十分小さい $h$ に対して誤差の大きさが定数倍の $h^p$ 以下となることを表す．
```

### 手計算で確かめる

$x' = 0.2\,x$，$x(0) = 100$ を刻み幅 $h = 1$ で3ステップ計算する．

| $k$ | $t_k$ | $x_k$ | 傾き $f(t_k, x_k) = 0.2\,x_k$ | $x_{k+1} = x_k + 1 \times 0.2\,x_k$ |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | 100 | 20 | 120 |
| 1 | 1 | 120 | 24 | 144 |
| 2 | 2 | 144 | 28.8 | 172.8 |
| 3 | 3 | 172.8 | | |

解析解は $x(3) = 100\,e^{0.6} = 182.21$ であり，Euler法の値172.8は約9.4小さい．
傾きを区間の始めの値で固定したために，増え方を過小に見積もっている．

````{note} 演習1：刻み幅を半分にして手計算する
電卓を使ってよい．

2. 刻み幅を半分にすると，誤差はおよそ何分の1になったか．
````

```{dropdown} 演習1の確認
$h = 0.5$ では，各ステップで $x_{k+1} = x_k + 0.5 \times 0.2\,x_k = 1.1\,x_k$ となる．
$100 \to 110 \to 121 \to 133.1 \to 146.41$ で，$t = 2$ の値は146.41である．

このように，Euler法では十分小さい刻み幅の範囲で，刻み幅を半分にすると大域誤差もおよそ半分になる．
```

## Pythonによる実装

### Euler法の関数

手計算の手順をそのまま関数にする．
右辺の関数 $f$，計算区間，初期値，刻み幅を引数で与え，時刻の配列と近似解の配列を返す．

```python
def euler(rhs, t_span, x0, h, args=()):
    """前進Euler法で初期値問題 x' = rhs(t, x, *args), x(t0) = x0 を解く．

    rhs: 右辺の関数．rhs(t, x, *args) の形で呼び出す．
    t_span: (t0, t_end) 計算区間．
    x0: 初期値．
    h: 刻み幅．
    args: rhs に渡すパラメタのタプル．
    戻り値: 時刻の配列 t と近似解の配列 x．
    """
    t0, t_end = t_span
    n_steps = int(round((t_end - t0) / h))
    t = t0 + h * np.arange(n_steps + 1)
    x = np.zeros(n_steps + 1)
    x[0] = x0
    for k in range(n_steps):
        x[k + 1] = x[k] + h * rhs(t[k], x[k], *args)
    return t, x
```

右辺の関数は，`solve_ivp`と同じ`rhs(t, x, パラメタ...)`の形で書く．
今回のモデルではパラメタは $r$ の1つである．

```python
def exponential_rhs(t, x, r):
    """dx/dt = r x の右辺．"""
    return r * x
```

## `solve_ivp`による数値シミュレーション

### 使い方

Euler法は原理が分かりやすいが，精度を上げるには非常に小さい刻み幅が必要になる．
実際の計算では，`scipy.integrate.solve_ivp`を使う．
この関数は，既定ではRunge–Kutta法の一種であるRK45を使い，各ステップの局所誤差の推定値に基づいて刻み幅を自動調整する．許容誤差は局所誤差の制御に用いられ，計算区間全体の誤差の上限を保証するものではない．`t_eval`は出力時刻を指定する引数であり，内部の刻み幅を直接指定するものではない．
導出はこの講義では扱わない．

基本の呼び出し方は次のとおりである．

```python
# 数値解を出力したい時刻
t_eval = np.linspace(t_span[0], t_span[1], 101)

sol = solve_ivp(exponential_rhs, t_span, [x0], t_eval=t_eval, args=(r,))

print("成功したか:", sol.success)
print("時刻の配列の形:", sol.t.shape)
print("解の配列の形:", sol.y.shape)
print("右辺を評価した回数:", sol.nfev)
```

引数と戻り値の対応を整理する．

| 引数・属性 | 意味 | 今回の値 |
| --- | --- | --- |
| 第1引数 | 右辺の関数 `rhs(t, x, *args)` | `exponential_rhs` |
| 第2引数 `t_span` | 計算区間 $(t_0, t_{\mathrm{end}})$ | `(0.0, 10.0)` |
| 第3引数 | 初期値．状態変数が1つでもリストで渡す | `[x0]` |
| `t_eval` | 解を出力する時刻の配列 | `np.linspace(0, 10, 101)` |
| `args` | 右辺に渡すパラメタのタプル | `(r,)` |
| `sol.t` | 出力時刻の配列 | 長さ101 |
| `sol.y` | 解の配列．行が状態変数，列が時刻 | 形は (1, 101) |
| `sol.y[0]` | 1つ目の状態変数の時系列 | $x(t)$ |

状態変数が1つでも`sol.y`は2次元配列になる．
$x(t)$ を取り出すには`sol.y[0]`と書く．
第10回で状態変数が2つになると，`sol.y[0]`と`sol.y[1]`を使う．

### Euler法および解析解との比較

```python
x_ivp = sol.y[0]
x_exact_eval = exponential_solution(sol.t, x0, r)

print(f"solve_ivp の x(10) = {x_ivp[-1]:.4f}")
print(f"解析解の x(10)     = {x_exact_eval[-1]:.4f}")
print(f"誤差               = {x_ivp[-1] - x_exact_eval[-1]:.4f}")
print(f"最大誤差（全時刻） = {np.max(np.abs(x_ivp - x_exact_eval)):.4f}")

t_euler, x_euler = euler(exponential_rhs, t_span, x0, 0.01, args=(r,))
print(f"Euler法 h=0.01 の x(10) = {x_euler[-1]:.4f}，ステップ数 = {len(t_euler) - 1}")
```

`solve_ivp`は，右辺を数十回評価するだけで，Euler法が1000ステップかけた結果と同程度以上の精度を出す．
以後の講義では，特に断らない限り`solve_ivp`を使う．
ただし，右辺の関数が滑らかでない場合（観測データを補間して使う第6回など）には注意が必要である．
Euler法は，数値解法が何をしているかを理解するための基準として覚えておく．

```{tip} 許容誤差の指定
`solve_ivp`の既定の相対許容誤差は`rtol=1e-3`である．
もっと高い精度が必要なときは`solve_ivp(..., rtol=1e-8, atol=1e-10)`のように指定する．
精度を上げるほど右辺の評価回数は増える．
必要な精度を満たすかは，解析解との比較や，許容誤差を小さくした再計算によって確認する．許容誤差と出力時刻の定義は[SciPy公式ドキュメント](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html)も参照すること．
```

## 誤差の分類

数値解と観測値の間に差があったとき，それが計算の問題なのかモデルの問題なのかを区別できないと手の打ちようがない．
刻み幅を小さくしても減らない差に対して刻み幅を小さくし続けるのは，計算時間を捨てているだけである．
そこで，この講義で扱う誤差を4種類に分けて整理しておく．

| 種類 | 何に由来するか | 刻み幅・許容誤差を変えると減るか | 今回の例 | 詳しく扱う回 |
| --- | --- | --- | --- | --- |
| 数値解法の誤差 | 微分方程式を離散的な更新式で置き換えること | 減る | Euler法 $h = 1$ 日での $x(10) = 619.2$（解析解 $738.9$，差 $-119.7$） | 第2回（今回） |
| モデルの誤差 | 現象に対する仮定が現実と異なること | 減らない | 指数成長モデルによる2020年の人口 $19223$ 万人（観測値 $12615$ 万人） | 第3回・第4回 |
| 観測の誤差 | 測定・集計・記録の不確かさ | 減らない | 人口が国勢調査年は調査値，それ以外の年は推計値であること | 第12回 |
| パラメタ推定の誤差 | 有限のデータからパラメタを決めること | 減らない | $r$ を1920年と1970年の2点だけから決めたこと | 第7回・第12回 |

減らせるのは1行目だけであり，残りの3つは計算をどれだけ精密にしても消えない．
人口の例では，数値解と解析解の差が最大約 $0.6$ 万人であるのに対し，解析解と2020年の観測値の差は約 $6600$ 万人である．
約4桁の差があるため，数値誤差だけでは観測値との差を説明できない．モデルの仮定，パラメタの推定期間，観測の定義を検討する必要がある．
この比較はモデルの見直しを検討する根拠になるが，残差をすべて構造による誤差と特定するものではない．

### Euler法の誤差の内訳

1行目の数値解法の誤差は，微分方程式を解く場面では次のように分けられる．

| 誤差 | 意味 | 大きさの目安 | 今回の例 |
| --- | --- | --- | --- |
| 局所打ち切り誤差 | 厳密な値から1ステップだけ進めたときに生じる誤差 | Euler法で $O(h^2)$ | 手計算の1ステップ目 $100 \to 120$（解析解は $122.14$） |
| 大域打ち切り誤差 | 局所打ち切り誤差が計算区間全体で蓄積した誤差 | Euler法で $O(h)$ | $h$ を1/10にすると $x(10)$ の誤差も約1/10になる |
| 丸め誤差 | 計算機が実数を有限桁の浮動小数点数で表すこと | 倍精度で1演算あたり相対 $10^{-16}$ 程度 | $h$ を小さくしすぎるとステップ数が増え，蓄積が無視できなくなる |
| 読み取りの誤差 | `t_eval`の間隔より細かい時刻を読み取れないこと | 出力間隔の程度 | 半減期の読み取り値 $2.4$ 時間（解析解 $\ln 2 / k = 2.31$ 時間） |

十分滑らかな解を安定に計算する範囲では，刻み幅を小さくすると打ち切り誤差は減少する．一方，演算回数が増えると丸め誤差の影響が無視できなくなる場合がある．
そのため，刻み幅を小さくし続けても総誤差が単調に減少するとは限らない．丸め誤差の累積の仕方は，方程式や演算順序にも依存する．
`solve_ivp`は，各ステップの局所誤差の推定値を許容範囲に収めるように刻み幅を調整する．打ち切り誤差と丸め誤差の合計を最小化する刻み幅を探索しているわけではない．
丸め誤差や桁落ちなど，浮動小数点数という表現方法そのものに由来する誤差は補遺2で扱う．

```{tip} 計算を精密にすれば現実に合う，は誤解である
刻み幅や許容誤差を段階的に厳しくし，結果の変化が観測値との差に比べて十分小さければ，数値誤差以外の要因を検討する根拠となる．
このとき必要なのは，より精密な計算ではなく，仮定の見直しかデータの見直しである．
逆に，観測値とよく合っていても，数値解法の誤差とモデルの誤差が偶然打ち消し合っている可能性がある．解析解が分かる場合や刻み幅を変えた場合と比べ，数値解自体の妥当性を確かめる習慣をつけること．
第12回では，上の4種類を改めて整理し，どの誤差をどう評価するかを扱う．
```

## まとめ

- 初期値問題は，微分方程式 $x'=f(t,x)$ と初期条件 $x(t_0)=x_0$ をともに満たす関数を求める問題である
- Euler法は $x_{k+1}=x_k+h f(t_k,x_k)$ により近似値を逐次計算する．十分小さい刻み幅の範囲では，大域誤差は $O(h)$ であり，同じ区間で刻み幅を半分にするとステップ数は2倍になる
- `solve_ivp`は，より高精度な方法と刻み幅の自動調整により，少ない計算量で精度の高い数値解を与える．呼び出し方は`solve_ivp(rhs, t_span, [x0], t_eval=t_eval, args=(パラメタ,))`で，解は`sol.y[0]`に入る
- 数値解と観測値の差には，数値解法の誤差とモデルの仮定による誤差がある．前者は計算を精密にすれば減るが，後者は減らない

## 補遺1：解の存在と一意性

この節は到達目標には含まれない．初期値問題に解があり，しかも1つに定まることを保証する定理を紹介する．

数値解法は，求めるべき解がそもそも存在し，しかもただ1つであることを前提として近似値を計算する．
一般の $f$ について，それがいつ保証されるかを述べたのが次の定理である．

```{important} 定理（Picard–Lindelöfの定理）
長方形領域

$$
D = \{(t, x) : |t - t_0| \le a,\ |x - x_0| \le b\}
$$

の上で $f(t, x)$ が連続であり，さらに $x$ についてLipschitz条件

$$
|f(t, x_1) - f(t, x_2)| \le L\,|x_1 - x_2|
\qquad ((t, x_1), (t, x_2) \in D)
$$

を満たす定数 $L > 0$ が存在するとする．
$M = \max_{(t, x) \in D} |f(t, x)|$，$\alpha = \min(a,\ b / M)$ とおくと，初期値問題

$$
\left\{
\begin{aligned}
\frac{dx}{dt} &= f(t, x) \\
x(t_0) &= x_0
\end{aligned}
\right.
$$

の解が区間 $|t - t_0| \le \alpha$ 上にただ1つ存在する．
```

Lipschitz条件は，$x$ を動かしたときの $f$ の変わり方に上限があることを表す．
$\partial f / \partial x$ が $D$ 上で連続ならその最大値を $L$ として条件が満たされるので，この講義で扱うモデルはいずれも条件を満たす．
今回の $f(t, x) = rx$ では $|r x_1 - r x_2| = |r|\,|x_1 - x_2|$ であり，$L = |r|$ ととれる．
以降は解の存在と一意性を前提として進める．

証明は本講義の範囲外であり，試験にも出さない．関心のある者のために以下に載せておく．

````{dropdown} 証明（Picardの逐次近似法）

**1. 積分方程式への書き換え**

$f$ が連続のとき，連続関数 $x(t)$ が初期値問題の解であることと，積分方程式

$$
x(t) = x_0 + \int_{t_0}^{t} f(s, x(s))\,ds
$$

を満たすことは同値である．
実際，解であれば微分方程式の両辺を $t_0$ から $t$ まで積分して上式を得る．
逆に上式を満たせば，右辺の被積分関数が連続なので微分積分学の基本定理から $x$ は微分可能で $x' = f(t, x)$ となり，$t = t_0$ を代入して $x(t_0) = x_0$ を得る．

**2. 完備距離空間の設定**

$I = [t_0 - \alpha,\ t_0 + \alpha]$ とし，

$$
X = \left\{ x \in C(I) \ :\ \max_{t \in I} |x(t) - x_0| \le b \right\}
$$

とおく．$X$ は連続関数の空間 $C(I)$（一様ノルム $\|x\| = \max_{t \in I}|x(t)|$ を入れると完備）の閉部分集合なので，それ自身が完備距離空間である．

**3. 写像 $T$ が $X$ を $X$ に移すこと**

$x \in X$ に対して

$$
(Tx)(t) = x_0 + \int_{t_0}^{t} f(s, x(s))\,ds
$$

と定める．$(s, x(s)) \in D$ だから $|f(s, x(s))| \le M$ であり，

$$
|(Tx)(t) - x_0| \le \left| \int_{t_0}^{t} |f(s, x(s))|\,ds \right| \le M\,|t - t_0| \le M\alpha \le b
$$

となる（最後の不等式は $\alpha \le b / M$ による）．よって $Tx \in X$ である．

**4. 反復回数に関する評価**

$x, y \in X$ について，$n \ge 0$ に対し

$$
|(T^n x)(t) - (T^n y)(t)| \le \frac{L^n\,|t - t_0|^n}{n!}\,\|x - y\|
$$

が成り立つことを $n$ についての帰納法で示す．$n = 0$ では両辺が一致する．$n$ で成り立つとすると，Lipschitz条件から

$$
\begin{aligned}
|(T^{n+1} x)(t) - (T^{n+1} y)(t)|
&\le \left| \int_{t_0}^{t} \left| f(s, (T^n x)(s)) - f(s, (T^n y)(s)) \right| ds \right| \\
&\le L \left| \int_{t_0}^{t} |(T^n x)(s) - (T^n y)(s)|\,ds \right| \\
&\le L \left| \int_{t_0}^{t} \frac{L^n |s - t_0|^n}{n!}\,\|x - y\|\,ds \right|
= \frac{L^{n+1}\,|t - t_0|^{n+1}}{(n+1)!}\,\|x - y\|
\end{aligned}
$$

となり，$n + 1$ でも成り立つ．

**5. 不動点の存在と一意性**

4の評価で最大値をとると

$$
\|T^n x - T^n y\| \le \frac{(L\alpha)^n}{n!}\,\|x - y\|
$$

を得る．$(L\alpha)^n / n! \to 0\ (n \to \infty)$ だから，十分大きい $n$ に対して $(L\alpha)^n / n! < 1$ となり，$T^n$ は $X$ 上の縮小写像である．
完備距離空間上の写像 $T$ について，ある $n$ で $T^n$ が縮小写像であれば $T$ はただ1つの不動点をもつ（Banachの不動点定理の系）．
その不動点 $x^{*}$ が積分方程式の唯一の解であり，1により初期値問題の唯一の解である．$\blacksquare$

**補足：$x' = rx$ での逐次近似**

$f(t, x) = rx$，$t_0 = 0$ とし，$x_0(t) \equiv x_0$ から出発して $x_{n+1} = T x_n$ を繰り返すと

$$
x_n(t) = x_0 \sum_{k=0}^{n} \frac{(rt)^k}{k!}
$$

となる．$n \to \infty$ の極限は指数関数の級数展開そのものであり，解析解 $x_0 e^{rt}$ に一致する．
````

## 補遺2：浮動小数点数と数値誤差

計算手順の近似や有限精度の演算によって，数学的に定まる値と計算結果の間に生じる差を**数値誤差**と呼ぶ．個々の演算や特別な問題では，結果が厳密に一致する場合もある．
その中身を見る前に，誤差の表し方を決めておく．
真の値を $x$，計算で得られた値を $\tilde{x}$ とすると，

$$
\text{絶対誤差} = |\tilde{x} - x|,
\qquad
\text{相対誤差} = \frac{|\tilde{x} - x|}{|x|} \quad (x \neq 0)
$$

である．
単位をもつ量の大きさを論じるときは絶対誤差を，桁数（有効数字）を論じるときは相対誤差を使う．
本文の表では，符号から過大評価か過小評価かが読み取れるように，絶対値をとらない $\tilde{x} - x$ も併用している．

数値誤差は，生じる原因によって次の5つに分けられる．

| 誤差 | いつ生じるか | 原因 | 対策 |
| --- | --- | --- | --- |
| 打ち切り誤差 | 無限回の操作を有限回で止めるとき | 微分方程式の離散化，級数の途中打ち切り | 刻み幅を小さくする，次数の高い解法を使う |
| 丸め誤差 | 実数を浮動小数点数で表すとき | 仮数部の桁数が有限であること | 原理的に避けられない．演算回数を減らして蓄積を抑える |
| 桁落ち | 値の近い2数を引くとき | 上位の桁が打ち消し合い，有効桁数が減ること | 引き算が起きないように式を変形する |
| 情報落ち | 絶対値の大きく異なる2数を足すとき | 小さい方の下位桁が丸めで消えること | 絶対値の小さい順に加える，`math.fsum`を使う |
| オーバーフロー／アンダーフロー | 表現できる範囲を超えるとき | 指数部の範囲が有限であること | 対数をとる，変数をスケーリングする |

打ち切り誤差は，離散化や有限項での近似に由来する．他の項目は有限精度の数値表現や演算に関係し，その影響は解法，式の変形，変数の尺度，演算順序によっても異なる．
倍精度（`float64`）では仮数部が53ビットで，相対精度はおよそ $2.2 \times 10^{-16}$（**計算機イプシロン**）である．
10進数でいえば有効数字は約16桁であり，それより細かい違いは表せない．

```python
import math

print(f"倍精度の計算機イプシロン: {np.finfo(float).eps:.3e}")

# 丸め誤差：10進数の0.1は2進数では有限桁で表せない
print("0.1 + 0.2 =", 0.1 + 0.2, " 0.3と等しいか:", 0.1 + 0.2 == 0.3)

# 桁落ち：値の近い2数を引くと有効桁数が減る
print("(1 + 1e-12) - 1 =", (1.0 + 1e-12) - 1.0, " 真値 1e-12")

# 情報落ち：絶対値の大きく異なる2数を足すと小さい方が消える
print("1e16 + 1.0 - 1e16 =", 1e16 + 1.0 - 1e16, " 真値 1.0")

# 加える順序で結果が変わる：0.1を100万回足す
terms = np.full(1_000_000, 0.1)
print("単純な総和:", sum(terms), " math.fsum:", math.fsum(terms), " 真値 100000.0")

# オーバーフロー：表せる最大値を超えると inf になる
print("表せる最大値:", np.finfo(float).max)
print("1e308 * 10 =", 1e308 * 10)
```

浮動小数点数の等値比較が危ういことが，最初の行から分かる．
`0.1 + 0.2 == 0.3`は`False`になるので，数値計算では`a == b`ではなく`abs(a - b) < 許容値`や`np.isclose(a, b)`で比較する．
3行目の桁落ちでは，真値 $10^{-12}$ に対して有効数字が4桁程度まで減っている．
4行目の情報落ちでは，$10^{16}$ に1を足しても値が変わらず，差が完全に0になっている．
5行目のように同じ数を足し合わせるだけでも，加える順序を変えれば結果が変わる．

```{warning} 浮動小数点数の落とし穴
`for`文で`t = t + h`と刻み幅を足し続けると，丸め誤差が蓄積して時刻がずれる．
本文の`euler`関数が`t = t0 + h * np.arange(n_steps + 1)`と掛け算で時刻を作っているのは，この蓄積を避けるためである．
同じ理由で，`while t <= t_end`のような浮動小数点数の比較でループを止めると，最後の1ステップが実行されたりされなかったりする．ステップ数を整数で決めてから`for`で回すほうが安全である．
```

### 刻み幅を小さくしすぎると精度が落ちる

打ち切り誤差と桁落ちが競合する様子は，Euler法を導いたときの差分商そのもので確かめられる．
$e^t$ の $t = 0$ における微分係数（真値は1）を $\dfrac{e^{h} - e^{0}}{h}$ で近似し，$h$ を小さくしていく．

```python
print(f"{'h':>8} {'近似値':>16} {'絶対誤差':>12}")
for h in [1e-1, 1e-2, 1e-4, 1e-6, 1e-8, 1e-10, 1e-12, 1e-14, 1e-16]:
    derivative = (np.exp(0.0 + h) - np.exp(0.0)) / h
    print(f"{h:8.0e} {derivative:16.12f} {abs(derivative - 1.0):12.3e}")
```

$h$ を $10^{-1}$ から $10^{-8}$ まで小さくする間は，誤差が $h$ に比例して減っていく．
これは打ち切り誤差が支配的な領域である．
ところが $h = 10^{-8}$ を境に誤差は増加に転じ，$h = 10^{-14}$ では $h = 10^{-4}$ のときより悪くなる．
$h = 10^{-16}$ では $e^{h}$ と $e^{0}$ が浮動小数点数として同じ値になり，分子が0，近似値も0になってしまう．
分子 $e^{h} - e^{0}$ で桁落ちが起きているためで，$h$ を小さくするほど2つの値が近づき，有効桁数が失われる．
誤差が最小になるのは，打ち切り誤差と桁落ちが釣り合う $h \approx \sqrt{\varepsilon} \approx 10^{-8}$ 付近である．

刻み幅は小さければ小さいほどよい，というわけではない．
どこまで小さくすれば十分かは，刻み幅を変えて結果が変わらなくなることを確認して決める．
## 自主学習用の発展問題

課題1・2を全てこなし，時間が余った場合に取り組んでよい．

````{note} 発展問題1：Runge–Kutta法の導出

Euler法は，区間 $[t_k, t_{k+1}]$ の傾きを始点の値 $f(t_k, x_k)$ だけで代表させていた．
区間の途中の傾きも使えば，同じ刻み幅でも精度を上げられる．
次の**2次のRunge–Kutta法（中点法）**を考える．

$$
\left\{
\begin{aligned}
k_1 &= f(t_k,\ x_k) \\
k_2 &= f\!\left(t_k + \tfrac{h}{2},\ x_k + \tfrac{h}{2}\,k_1\right) \\
x_{k+1} &= x_k + h\,k_2
\end{aligned}
\right.
$$

まず $k_1$ で区間の中点における状態を予測し，そこで評価し直した傾き $k_2$ で1ステップ分進める，という2段階の手続きである．

1. $x(t_k + h)$ を $h$ について2次までTaylor展開し，$x'' = f_t + f_x\,f$ を使って
   $x(t_k + h) = x_k + h f + \frac{h^2}{2}\left(f_t + f_x f\right) + O(h^3)$
   となることを示す（右辺の $f$ とその偏導関数は $(t_k, x_k)$ での値とする）．
2. $k_2$ を2変数のTaylor展開で $h$ の1次まで展開し，$x_{k+1}$ が1の右辺と $O(h^3)$ まで一致することを確かめる．局所打ち切り誤差が $O(h^3)$，大域誤差が $O(h^2)$ になることが分かる．
3. 本文の`euler`関数にならって`rk2(rhs, t_span, x0, h, args=())`を実装する．
4. $x' = 0.2\,x$，$x(0) = 100$，計算区間0〜10日について，$h = 1, 0.5, 0.1, 0.01$ でEuler法とRK2の $t = 10$ における絶対誤差を求め，`ax.loglog`で両対数グラフに描く．
5. 両対数グラフの傾きが，Euler法で約1，RK2で約2になることを確かめる．この傾きが収束次数に対応する理由を説明する．
6. `solve_ivp`が既定で使うRK45はさらに高次の方法である．同じ問題でRK45の絶対誤差と`sol.nfev`を調べ，同程度の精度を出すのにRK2が何ステップ必要かと比べる．
````

### Euler法の不安定性

減衰モデル $x' = -kx$ をEuler法で解くと，更新式は $x_{k+1} = (1 - hk)\,x_k$ になる．
$hk > 2$ のとき $|1 - hk| > 1$ となり，数値解は符号を変えながら発散する．
本来は単調に減るはずの解が，計算の仕方のせいで振動して増えてしまう．

````{dropdown} 発展演習：Euler法の不安定性

```python
k = 2.0
x0_decay = 100.0
t_span_decay = (0.0, 10.0)

fig, ax = plt.subplots(figsize=(7, 4))
t_fine = np.linspace(0.0, 10.0, 201)
ax.plot(t_fine, x0_decay * np.exp(-k * t_fine), color="black", label="analytical solution")
for h in [0.4, 0.9, 1.2]:
    t, x = euler(decay_rhs, t_span_decay, x0_decay, h, args=(k,))
    ax.plot(t, x, marker="o", markersize=3, linestyle="--", label=f"Euler, h = {h} (hk = {h * k:.1f})")
ax.set_title("Euler method for dx/dt = -2 x with large step sizes")
ax.set_xlabel("Time [arbitrary unit]")
ax.set_ylabel("x [arbitrary unit]")
ax.set_ylim(-300, 300)
ax.grid(True)
ax.legend()
fig.tight_layout()
fig.savefig(FIGURE_DIR / "euler_instability.png", dpi=150)
plt.show()
```

1. $hk < 1$，$1 < hk < 2$，$hk > 2$ の3つの場合で数値解の振舞いがどう違うかを説明する．
2. 同じ問題を`solve_ivp`で解き，解析解との絶対誤差を評価する．
3. 減衰が速い（$k$ が大きい）現象ほど，Euler法では小さい刻み幅が必要になる理由を説明する．
````

この現象は数値解法の**安定性**の問題であり，刻み幅を選ぶときの注意点として知っておくとよい．
`solve_ivp`も数値解法であるため，計算の成功・失敗と，許容誤差を変更したときの結果の変化を確認する必要がある．

````{note} 発展問題2：後退Euler法と数値的安定性

上で見たように，Euler法は $hk > 2$ で発散した．
区間の傾きを始点ではなく**終点**の値で評価する方法を**後退Euler法**（陰的Euler法）と呼ぶ．

$$
x_{k+1} = x_k + h\,f(t_{k+1},\ x_{k+1})
$$

右辺に $x_{k+1}$ が現れるため，一般には各ステップで $x_{k+1}$ に関する方程式を解く必要がある．
次の時刻の未知値を右辺にも含む更新式を陰的な方法と呼ぶ．一般には各ステップで代数方程式を解く必要があり，計算量はその求解方法にも依存する．

1. $f(t, x) = -k\,x$ の場合に上の式を $x_{k+1}$ について解き，$x_{k+1} = \dfrac{x_k}{1 + h k}$ となることを示す．
2. 任意の $h > 0$，$k > 0$ に対して $0 < \dfrac{1}{1 + hk} < 1$ であることから，刻み幅によらず数値解が単調に減少して0に近づくことを示す．前進Euler法の増幅率 $1 - hk$ と比べ，どこが違うかを述べる．
3. 後退Euler法を実装し，$x' = -2x$，$x(0) = 100$，計算区間0〜10について $h = 0.4,\ 0.9,\ 1.2$ で計算して，上の図と並べて描く．
4. 後退Euler法は安定だが，大域誤差は前進Euler法と同じ $O(h)$ である．$h = 1.2$ での解析解との絶対誤差を求め，数値解の安定性と近似精度が別であることを確認する．
5. 減衰の速い成分と遅い成分が混ざった問題を**硬い問題**（stiff problem）と呼ぶ．陽的な方法は速い成分に合わせた小さい刻み幅を強いられるため，こうした問題では陰的な方法が使われる．`solve_ivp`で`method="Radau"`や`method="BDF"`を指定し，$k$ を大きくした問題で既定のRK45と`sol.nfev`を比べる．
````
